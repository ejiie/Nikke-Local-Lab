# 신규 보스·보정 FX 사용자 실게임 검증

2026-09-13 담당 범위: 게임 실행·화면/전투 판정은 운영자, 구현·오프라인/자동 검사·
검증용 배포·복구 도구·CI/병합은 에이전트가 맡는다. **기존 151/S26 인수는 완료**이며
이 문서는 기존 S26을 처음부터 다시 검증하라는 요청이 아니다.

## 실행 전 인계 조건

S29의 5개 검증용 실행 구성은 하나의 기존 UserValidation client를 공유한다. 상위
controller의 Inspect와 실제 compiled-plan 결박 검사를 모두 통과했다. 설치 앱의
현재 적용/CI 상태는 [HANDOFF](../HANDOFF.md)의 최신 마감 절을 기준으로 한다.
`실게임 검증 대기`는 조립·전달 준비 상태이며 전투/FX 인수나 운영 profile 활성화가 아니다.
미처리 다른 시즌의 가져오기는 자동 조립을 수행하지만 전달/자료 결손을 완료로 숨기지 않는다.

현재 보정 FX는 오프라인 후보다. 아래 조건을 갖춘 **새 검증용 실행 구성을 인계받은 뒤**
검증한다. `artifacts`의 CDB·bundle을 공식 설치본이나 운영 캐시에 수동 덮어쓰지 않는다.

- 선택 시즌·보스·기본 약점과 이번 실행 약점이 표시되는 준비 상태
- 검증된 v6/운영 DB/공유 캐시와 분리된 실행 대상 및 변경 파일 hash/원복 기준
- 관리자 실행을 유지하면서 프로세스 Job과 승인된 ACE 서비스 범위를 관리하는 실행기
- 필요한 드라이버 전환의 별도 승인 및 종료 시 정상 원복 절차
- 시작 실패/중도 종료/재시도 상태와 원복 결과를 확인할 수 있는 경로

이 조건은 S29의 봉인된 5속성 전달 계획으로 확인한다. 오프라인 검사를 실제 게임의
정상 동작 증거로 승격하지 않는다. 승인된 ACE-ADVT 자동 시작/종료 후 정상 중지만 허용하며
ACE-BASE·드라이버 파일·시작 유형을 바꾸지 않는다.

## 이번 인계의 실행 순서

1. 다른 NIKKE/공식 런처/이전 검증 게임을 종료한 상태에서 평소 관리도구를 연다.
   `솔로 레이드 → 시즌 선택 → SEASON 29`를 선택한다. 단일 마더 웨일 카드와
   5속성, 별도 사용자 검증 영역이 보여야 한다. 기본 약점 표시는 철갑으로 유지한다.
2. **수냉부터** 선택하고 `검증 계정으로 게임 시작`을 누른 뒤 UAC를 승인한다.
   준비된 별도 계정/독립 서버를 사용하며 현재 편집 계정·운영 DB/v6를 사용하지 않는다.
   승인 뒤에도 약 19GB 입력 전체 해시를 읽는 사전 검사가 있어 수 분 걸릴 수 있다.
   새 창을 여러 개 열거나 버튼을 반복 누르지 않는다.
3. 로비의 기존 진행도·튜토리얼 재등장 여부, S29 Challenge 진입, 아래 표의
   소환/부위/페이즈/QTE와 실드·보정 FX를 확인한다. 시작 후 제한은 약 20분이다.
4. 게임을 정상 종료하고 관리도구의 **`검증 실행 종료 · 원복 완료`**까지 기다린다.
   실패 코드가 함께 있으면 원복만 성공한 것이므로 실행 성공으로 보고하지 않는다.
5. 수냉이 정상이라면 작열 → 풍압 → 전격 → 철갑을 같은 방식으로 확인한다.
   속성마다 다른 준비 계정/서버를 쓰지만 client 사본은 같은 한 개다.

UAC를 취소했거나 사전 검사가 실패해 실제 실행을 시작하지 않았다면 버튼으로 다시 요청할
수 있다. 실제 실행을 시작한 각 봉인 구성은 **1회용**이며 완료 후 재사용하지 않는다.
동일 약점 재검증이 필요하면 새 assessment/작은 실행 계획을 발급한다. 전체 게임 복제는
추가하지 않는다. 이번에는 5개 첫 검증 구성을 인계하며 자동 무제한 재시도는 제공하지 않는다.

`원복 필요`이면 그 약점의 **`원복 재개`**만 누르고 UAC를 승인한다. 상태 불명·큰 파일
변경·원복 실패가 계속되면 추가 실행을 멈추고 표시된 코드를 전달한다. 파일/marker를
직접 삭제하거나 보안 서비스를 수동 강제 종료하지 않는다. 앱 조회/새로고침은 실행이나
복구를 자동 시작하지 않는다. 시스템 공유 설정을 쓰는 동안 다른 게임은 실행하지 않는다.

## 사용자가 확인할 항목

| 구분 | 확인할 내용 | 성공 판단 |
| --- | --- | --- |
| 시즌 선택 | 같은 보스의 다른 시즌이 별개이며 선택 시즌으로 Challenge 진입 | 화면 시즌·보스·패턴이 선택한 시즌과 일치 |
| 원본 FX 기준 | 이번 철갑 약점 구성의 원본 FX 관찰 | 기준 화면을 기록하며 다른 보정의 수락으로 처리하지 않음 |
| 보정 FX | 보정 대상 쉴드의 생성·유지·파괴 시점 | 보스에 맞는 위치/크기, 잘림·치우침·과도한 확대 없음 |
| 5약점 | 작열·수냉·풍압·전격·철갑을 실행 전에 각각 선택 | 선택 약점 표시와 실제 공격 유효성 일치 |
| 속성 실드 | 같은 속성과 다른 속성 공격을 비교 | 시즌 원래 실드 규칙을 유지하면서 선택 속성에 맞게 작동 |
| S29 패턴·QTE | 소환·부위·페이즈 전환 및 속성 QTE | 누락·멈춤 없이 진행, QTE 허용 속성과 표시 일치 |
| 결과·다음 속성 | 결과창/중도 종료 후 원복 상태 확인, 다음 속성 실행 | 미복구 중 새 실행 차단, 원복 후 다음 구성 실행 가능 |
| 원복 | 매 실행 후 입력 원복 완료 표시 | 다른 속성에 보정 잔류 없음; 파일 hash 확인과 화면 판단은 별개 |

보스 **약점**과 보스 자체 **속성**은 다르다. 현재 변형 규칙은 다음과 같다.

| 선택 약점 | 보스 자체 속성 | 새 Transform 보정 대상 |
| --- | --- | --- |
| 작열 | 풍압 | 해당 |
| 수냉 | 작열 | 해당 |
| 풍압 | 철갑 | 해당 |
| 전격 | 수냉 | 기존 정확한 매핑 확인 |
| 철갑 | 전격 | 원본 기준 FX |

기본 약점 표시는 실행 약점 변경 후에도 해당 시즌 원본 값으로 유지해야 한다.
한 속성의 성공을 나머지 속성 성공으로 확대하지 않는다.

## 결과 전달

시즌·선택 약점·실패 시점(진입/실드 생성/실드 파괴/QTE/결과/종료)과 화면 증상을 알려준다.
가능하면 해당 순간 스크린샷을 첨부한다. 실제 계정 인증값·토큰이나 원본 리소스를
GitHub에 첨부하지 않는다. 재다운로드·무결성·관리자/서비스 경고가 뜨면 임의로 설치를
진행하거나 원본 캐시를 바꾸지 말고 그 화면을 먼저 전달한다.

자동 로그는 요청/파일/프로세스 관측 근거이며, 화면 정상·전투 정상 판정은 사용자
확인으로 별도 기록한다. 실패 실행 receipt는 원복 성공으로 덮어쓰지 않는다.
## 초기 오류 진단 로그 — 2026-09-13

오류 기록 보강 앱을 설치한 뒤 새 사용자 실행은 기존 run 아래
`ui-actions/<operationUid>/`에 다음 파일을 남깁니다. 이전 실패 폴더는 보존합니다.

- `diagnostic.started.json`: controller의 첫 사전 검사보다 먼저 기록하는 시작 증거.
- `controller-diagnostic.json`: 제어된 오류 코드, 예외/내부 예외 종류, HResult/Win32
  코드, 프로젝트 스크립트/행, 최근 오류 이력과 정상 반환/실패 구분.
- `process-exit.json`: 상위 프로세스 종료 코드 및 controller 최종 로그 존재 여부.
- `launch-error.json` / `action-error.json`: 프로세스 생성 실패 또는 API 완료 처리 오류.

raw 메시지·인자·source line·target은 저장하지 않으며 메시지는 비가역 hash로만
구분합니다. 오류 이력에는 처리된 오류도 있으므로 전부 직접 원인으로 취급하지 않습니다.
강제 종료나 PowerShell 자체 시작 실패에는 최종 controller 로그가 없을 수 있습니다.
첫 로그를 만들 수 없으면 controller를 시작하지 않습니다. 이 파일들은 Git 외부의
진단 증거이며 실행/원복 성공 또는 실제 전투 인수 증거를 대신하지 않습니다.
