# 라피: 레드 후드 — 발사 조건과 교체 무기의 실전 관측

2026-09-19. 운영자가 완료를 알린 울트라 솔로 실전 1건을 조사했다. 실행 DB의 전투 키와 수집 영수증, 로그의 캐릭터를 대조했다. 전체 편성·원본 게임 ID·계정 정보는 로컬 private 자료에만 보관한다.

결론: **버스트가 아닌 발사 수 조건에서 시작하는 라피의 교체 공격을 실제 로그에서도 연결할 수 있다.** 현재 장착 무기만 확인하거나 ChangeAmmo.ammoDelta를 그대로 발사 수로 세는 방식으로는 제대로 해석할 수 없다.

분석 사본과 스크립트는 Git 제외 경로 `artifacts/battlelog-capture-20260919/analysis/rapi/`에 있다. 이번 결과는 분석이며 운영 DB·런타임·통계 UI를 변경한 것은 아니다.

## 입력과 확인 범위

- 보고서 시간 180,000ms, TickClock 누적 플레이 시간 180,109ms.
- 원본 139,605bytes → raw DEFLATE 해제 1,609,108bytes → 165,852개 이벤트를 EOF까지 해석.
- SHA-256: `a5b0c4e708754e437f8965894427c8bf3b305e905cafd9a04f1512eeaea42b93`.
- 시간은 틱 누적값이다. 같은 틱 안의 사건 순서는 이벤트 순번으로 보존하며, 틱 내부의 실시간 간격은 확정하지 않는다.

## 패시브 → 교체 → 발사체 연결

정적 데이터에서 확인했던 경로를 실제 기록과 연결했다.

```text
스킬 2의 OnUseAmmo 조건
→ UseCharacterSkillId가 가리키는 ChangeWeapon 스킬
→ UseCharacterSkill(skillIndex=4, skillType=2)
→ ChangeWeapon: 기본 MG → StickyProjectileDirect / RL 설정
→ ProjectileSpawn: 소유자=라피, 발사 설정=해당 교체 무기
→ ChangeWeapon: 기본 MG로 복귀
→ 이후 CommonHurtEvent.rawCaster로 발사체의 피해 추적
```

- 실제 교체·복귀는 **101회**, 모두 정적 스킬 2 경로의 ChangeWeapon 스킬과 일치했다.
- 각 교체 구간에 해당 무기의 ProjectileSpawn이 **정확히 1개씩** 있다.
- 98회는 시작과 복귀가 같은 틱이며, 나머지 3회는 17ms 뒤 복귀했다. 무기 교체의 지속 시간이 로그상 0ms라고 해서 공격이 없었던 것은 아니다.
- 교체 설정은 `DurationType=Shots`, `DurationValue=1`, ShotCount=1, MuzzleCount=1, MaxAmmo=1이다.
- 발사체 101개 중 100개에 연결된 피해 이벤트가 있으며, 총 308개다. 67.499초에 생성된 나머지 1개에는 이 경로로 연결되는 피해 기록이 없다. 이를 명중·빗나감·삭제 중 하나로 임의 확정하지 않는다.
- 피해가 확인된 발사체의 첫 피해 지연은 **143–194ms**, 마지막 피해까지의 최대 간격은 **2,667ms**다.

자신이 발사한 발사체를 rawCaster로 추적하는 것과, 적 투사체를 공격한 피해를 분리하는 것은 다른 작업이다. 전자는 공격 출처이고 후자는 피격 대상 분류다.

## 버스트 사용 여부와 발동 간격

이번 전투는 라피와 레이븐의 버스트 III가 번갈아 사용됐다. 종료가 기록된 풀버스트는 각각 7개이며, 전투 종료 직전 라피 풀버스트가 하나 더 시작해 약 17ms만 기록됐다. 마지막 짧은 구간은 자연 만료된 풀버스트로 취급하지 않는다.

정적 기본 조건은 OnUseAmmo의 **120**이다. 라피 버스트 경로에는 `TimingTriggerValueChange`, `ValueType=Integer`, 값 **-60**이 있다. 해당 효과의 라피 대상 AddedFunction도 각 라피 버스트 시점에서 관측됐다. 이는 조건을 60 줄이는 설정이며, 최종적으로 60을 의도한 데이터다. 발동 지연·카운터 경계까지 포함한 런타임 내부 카운터를 직접 읽은 것은 아니다.

| 교체 발동 시점 | 교체 횟수 |
|---|---:|
| 본인이 참여한 풀버스트 | 61 |
| 다른 캐릭터가 III를 사용한 풀버스트 | 27 |
| 풀버스트 밖 | 13 |
| 합계 | 101 |

서로 인접한 두 교체 발동 사이에 풀버스트 진입·종료가 없는 구간만 비교했다.

| 구간 | 비교 간격 수 | 기본 무기의 isUse 이벤트 수 | 발동 간격 중앙값 |
|---|---:|---|---:|
| 라피 참여 풀버스트 | 54 | 59회×11, 60회×35, 61회×8 | 1,127.5ms |
| 레이븐 참여 풀버스트 | 20 | 118회×1, 119회×3, 120회×13, 121회×1, 122회×1, 123회×1 | 2,246ms |

따라서 발사 조건 변경에 따른 실전 간격 차이가 관측된다. 다만 이를 ‘로그의 매 60번째/120번째 이벤트와 정확히 같은 위치에서 발동한다’로 바꾸면 안 된다. 이벤트 반영 시점과 내부 조건 카운터가 동일한지, 경계에서 어떤 발사가 집계됐는지는 미확정이다. 첫 발동 및 상태를 넘나드는 간격은 위 중앙값 비교에서 제외했다.

## ChangeAmmo의 함정

첫 교체 발사에서 기록된 ammoDelta는 **-556**, 기본 무기로 돌아온 뒤의 다음 isUse 이벤트에는 **+555**가 기록됐다. 그러나 이 교체 구간에서 생성된 발사체는 1개다. 다음 교체에서도 -496 → 다음 기본 사격 +495와 같은 형태가 반복된다.

이는 서로 다른 무기의 탄창으로 바뀌면서 잔탄 기준이 달라지는 값이 섞여 있음을 보여 준다. ‘음수 크기=발사 수’, ‘양수이면 사격 아님’으로 처리하면 안 된다. 이 표본의 기본 무기 isUse 이벤트에는 양수 증감 기록도 99개 있다.

분석에 사용할 구분:

- 탄약 상태의 변화량: 원본 ammoDelta를 그대로 보존.
- 기본 무기 사용 관측: shot 참조와 isUse 이벤트를 기준으로 집계하되, 내부 트리거 카운터와 구분.
- 라피의 패시브 교체 발사: 교체 구간별 ProjectileSpawn과 소유자·shot이 일치하는지 확인.

## 피해의 출처와 발생 시점

첫 교체는 4.070초에 발생하고 같은 틱에 MG로 복귀했다. 이 발사체는 4.226초에 본체 및 여러 부위에 총 5개 피해 이벤트를 남겼다. 피해 당시 장착 무기만 보면 MG 피해로 오분류할 수 있다.

원본 발사체 참조를 따라가면 다음을 함께 저장할 수 있다.

1. 원천 스킬: 라피 스킬 2에서 호출한 교체 공격.
2. 공격 방식: 교체 무기의 발사체.
3. 생성 시점의 버스트 구간.
4. 피해 발생 시점의 버스트 구간.
5. 피해 대상과 각 타격의 판정.

연결된 피해 308개에는 ‘풀버스트 밖 생성 → 풀버스트 안에서 피해’, ‘본인 풀버스트에서 생성 → 다른 풀버스트에서 피해’ 사례도 있다. 생성 시점의 버스트 구간을 피해 발생 시점으로 그대로 복사하면 안 된다.

| 생성 구간 → 피해 구간 | 피해 이벤트 수 |
|---|---:|
| 본인 참여 → 본인 참여 | 188 |
| 다른 풀버스트 → 다른 풀버스트 | 77 |
| 밖 → 다른 풀버스트 | 16 |
| 밖 → 본인 참여 | 13 |
| 밖 → 밖 | 11 |
| 본인 참여 → 밖 | 1 |
| 본인 참여 → 다른 풀버스트 | 2 |

## 피해 집계와 계수 연결

발사체 참조로 귀속한 308개 적용 이벤트는 같은 틱·공격자·대상·교체 shot·부위·피해량 조건에서 각각 유일한 선행 DamageFormula와 연결됐다. 사거리 판정은 전부 false, 계수는 1.0이었다.

전체 CommonHurtEvent를 무조건 합산하면 이 표본의 라피 TAB 값보다 **8,718,145**가 많다. 추가분은 별도 대상 kind 6·8에 대한 피해이며, 보스 대상 기록만 모으면 TAB와 일치한다. 임의로 전체 Common 합계를 TAB라고 표시하지 않는다. 이 관측을 모든 보스·모드의 전역 집계 규칙으로 승격하지 않는다.

이번 표본에서 TAB와 일치하는 보스 대상 적용 피해 분해:

| 관측 분류 | 피해 |
|---|---:|
| 기본 사격 계열, 라피 발사체 참조 없음 | 2,713,170,955 |
| 스킬 2 교체 발사체에 연결된 피해 | 3,208,811,264 |
| Function 피해 계열 | 792,424,173 |
| 별도 skill 계열 이벤트 7개 | 0 |
| 합계 / TAB | **6,714,406,392** |

이는 관측 경로에 따른 분류다. Function 피해 7개를 최종 표시용 스킬 이름에 귀속하는 작업은 별개다. 교체 발사체 내부의 충돌·폭발 구분은 아래 후속 분석에서 계산 계수와 활성 효과를 대조해 해결했다. 같은 발사체의 본체 피해가 여러 개라는 이유만으로 순서에 따라 효과 이름을 배정하지 않는다.

## 후속: 충돌·폭발 피해 분해

운영자가 효과별 분해를 요청한 뒤 동일 전투의 DamageFormulaShape와 활성 Function을 대조했다. **이번 라피 표본의 발사체 피해 308개는 모두 충돌 또는 폭발로 분리됐다.** HitContext에 효과명이 직접 없더라도, 계산에 사용된 전용 계수를 통해 구별할 수 있었다.

| 분류 | 충돌 계수 | 폭발 계수 | 전체 타격 수 |
|---|---:|---:|---:|
| 충돌, 기본 효과 | 2.5072 | 1.0 | 39 |
| 충돌, 버스트 효과 포함 | 약 6.7192 | 1.0 | 61 |
| 폭발 | 1.0 | 약 2.9263 | 208 |

원본 필드는 `stickyProjectileCollisionDamageRateBits`, `projectileExplosionDamageRateBits`이며 float32로 해석한다. 모든 타격에서 두 계수 중 하나만 비중립 값이다. DamageFormula와 CommonHurtEvent는 앞서 확인한 틱·공격자·대상·shot·부위·피해량의 유일 대응을 사용했다.

### 효과와 계수의 대조

AddedFunction/AddedIterationFunction/RemovedFunction을 이벤트 순서대로 반영하고, 라피를 대상으로 활성화된 해당 효과의 값과 스택을 합산했다. 308개 전부 기록된 계수와 오차 0.00001 이내로 일치했다.

- 기본 충돌: `1 + 1.5072 = 2.5072`. 라피 스킬 2 경로의 StickyProjectileCollisionDamage.
- 강화 충돌: `1 + 1.5072 + 4.2120 = 6.7192`. 위 기본 효과에 라피 버스트 경로의 충돌 피해 효과가 더해짐.
- 폭발: `1 + 1.0060 + 0.9203 = 2.9263`. 라피의 ProjectileExplosionDamage와 **아니스: 스타가 라피에게 부여한** ProjectileExplosionDamage가 더해짐. 효과를 건 캐릭터도 AddedFunction.caster로 확인했다.

수치가 크다는 이유로 충돌로 분류한 것이 아니다. 실제 전용 계수와 활성 효과 종류로 구분했다. 아니스의 버프가 기여하더라도 해당 타격의 공격자는 라피다. 버프 기여값과 피해 소유자를 서로 바꾸지 않는다.

### 피해 합계

TAB 비교에 사용했던 보스 대상 기준:

| 효과 | 타격 수 | 피해 |
|---|---:|---:|
| 충돌 | 100 | **1,593,312,162** |
| 폭발 | 206 | **1,615,499,102** |
| 교체 발사체 합계 | 306 | **3,208,811,264** |

별도 대상에 대한 폭발 2타격·7,496,516은 이 표에서 제외했다. 이를 포함한 전체 발사체 기록은 충돌 100타격·1,593,312,162와 폭발 208타격·1,622,995,618이며 합계 3,216,307,780이다. 보스 대상 합계와 전체 이벤트 합계를 혼용하지 않는다. 이 수치는 관측 피해 집계이며 버프를 제거한 가상 기여도나 최종 보스 HP 감소량을 재계산한 값이 아니다.

### 같은 발사체 안의 타격 구성

피해가 있는 발사체 100개는 모두 충돌 1타격씩이다. 폭발은 타격 대상 부위에 따라 분리된다.

| 발사체 하나의 기록 | 발사체 수 |
|---|---:|
| 충돌 1 + 폭발 1타격 | 1 |
| 충돌 1 + 폭발 2타격 | 93 |
| 충돌 1 + 폭발 3타격 | 3 |
| 충돌 1 + 폭발 4타격 | 3 |

‘폭발 4타격’은 폭발이 네 번 발동했다는 의미가 아니다. 같은 폭발이 본체·부위 등에 남긴 피해 이벤트 수다. 같은 본체에 충돌과 폭발이 각각 피해를 줄 수 있으므로 대상과 부위만으로 둘을 합쳐서는 안 된다.

첫 발사체는 4.226초에 다음 피해를 남겼다:

- 본체 충돌: 12,518,138, 비크리티컬.
- 본체 폭발: 8,993,542, 크리티컬.
- 다른 세 부위 폭발: 각 6,813,610, 비크리티컬.

같은 발사체의 같은 틱·같은 본체라도 충돌과 폭발의 크리티컬 판정은 독립적으로 기록된다. 판정을 발사체 단위로 하나만 보관하면 이 차이를 잃는다.

### 충돌과 폭발의 시간도 분리

100개 중 88개는 충돌과 첫 폭발이 같은 틱이고, 12개는 폭발이 나중에 기록됐다. 12개 모두 충돌 당시 StickyProjectileInstantExplosion 효과가 비활성이었고, 폭발 시점에는 활성이었다.

예: 38.720초 생성 → 38.882초 충돌 → 41.194초 레이븐 풀버스트 진입 → **41.211초 폭발**. 충돌 피해와 폭발 피해는 서로 다른 전투 단계에 귀속된다.

12개 중 11개는 다음 풀버스트 진입 17ms 뒤에 폭발했다. 나머지 1개는 167.327초 진입 뒤 238ms 후에 폭발했다. 효과 활성화와 실제 폭발 처리가 항상 같은 틱이라고 강제하지 않는다. 지연 238ms의 내부 처리 원인은 이 기록만으로 확정하지 않는다.

### 통계 분류 규칙과 적용 한계

이번 분석의 타격별 결과는 `effect-hits-classified.private.json`, 합계·대조 결과는 `effect-split.private.json`에 저장했다. 운영 DB나 UI에 새 컬럼을 설치한 것은 아니다.

- 공통 출처: 라피 스킬 2 → 교체 발사체.
- 세부 효과: `collision` 또는 `explosion`.
- 각 타격마다 실제 피해·크리/코어/사거리·대상 부위·발생 시각·계수 및 효과 제공자를 유지.
- 탄 생성, 충돌, 폭발 시점의 전투 단계를 별개로 보존.
- 두 전용 계수가 모두 1이거나 모두 비중립이면 이 규칙만으로 분류하지 않고 unresolved로 남김.

따라서 이 분해는 이번 라피 표본에서 확인한 규칙이다. 전용 계수가 중립인 다른 캐릭터·다른 빌드까지 검증 없이 일반화하지 않는다.

## 확정과 남은 부분

**실전 확인됨:** 발사 조건에서 호출되는 ChangeWeapon 출처, 101회의 생성·복귀·발사체 연결, 버스트 여부에 따른 발동 간격 차이, 복귀 이후의 피해 귀속, 타격별 사거리 판정, 생성·피해 구간 분리, 충돌·폭발 308타격 분류와 활성 효과 계수 일치.

**추가 해석 필요:** 내부 OnUseAmmo 카운터의 정확한 경계, 피해 기록이 없는 발사체 1개의 종말 원인, 폭발 처리 지연의 내부 사유, 전체 대상·모드에 공통인 TAB 포함 규칙. 이 부분은 추정으로 채우지 않는다.
