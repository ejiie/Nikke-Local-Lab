# 레이드 실제 기록·개인별 투사체 차감값

2026-09-20 운영자 요청: 솔로 Challenge 모의전에도 BattleLog를 연결하고, 실제 기록을 조회하며, 캐릭터별 기본 피해량은 적 투사체 피해를 제외한다. 편성에는 정사각형 초상화를 표시한다. 이는 앞선 모의전 수집 보류를 해제한 명시적 요청이다.

## 적용 내용

- 기존 `/soloraid/practice/setdamage`의 승인된 Challenge 덱 receipt에 숫자 통계와 BattleLog 분석을 연결했다. 기존 전투 키를 그대로 사용하며 `solo_challenge_practice`로 실전과 구분한다. 재전송은 같은 receipt를 사용한다. 결과 계산·일일 참여 규칙은 변경하지 않았다.
- V0028은 모의전 모드를 허용하고 `raid_projectile_analysis`, `raid_character_projectile_damage`를 추가한다. 개인별 분석 행은 기존 `(battle_uid, ordinal)` 딜표를 FK로 참조한다. 원래 TAB/결과창 값을 덮어쓰지 않는다.
- 개인별 표시는 캐릭터 TAB − 해당 캐릭터의 적 투사체 피해로 고정한다. 2026-09-20 운영자 정정으로 원값 전환 버튼을 제거했다. 로그·귀속 근거가 없는 기록은 ‘분석값 없음’이며 원래 피해를 차감값으로 대신 표시하지 않는다.
- 개인딜은 최대 차감값을 100%로 하는 막대로 표시한다. 편성 순서를 유지하며, 모두 분석된 덱의 양수 피해에 대해 1위는 RGB(166,48,48), 2위는 RGB(176,125,125), 나머지는 회색이다. 제공된 공식 스크린샷에서 추출한 색과 왼쪽의 어두운 그라데이션을 사용한다. 동률은 같은 순위이며 그 다음 순위는 건너뛴다. BigInt로 비교·비율을 계산하여 큰 피해 수치를 보존한다. 피해 외의 방어·회복 지표는 추가하지 않았다. 브라우저 검사·실제 얼굴 이미지 표시를 확인하고 정적 파일 3개를 설치했다. 증거는 Git 제외 `artifacts/raid-damage-bars-20260920/`에 있다.
- 목록과 상세에 로컬 presentation catalog의 캐릭터 UUID로 연결한 정사각형 초상화를 넣었다. 결과창 총 대미지 아래의 보조 문구는 제거 상태를 유지한다.
- 실제 목록 API는 `/admin-api/v1/accounts/{accountUid}/raid-records`다. 계정·시즌·레이드 종류·보스 순번·실전/모의전·약점으로 SQL에서 제한하고 시각/전투 UID cursor로 100건씩 조회한다. UI에 새로고침·더 보기를 제공한다. 피해량은 JSON 문자열이다.
- API는 기존 관리 세션 인증 경계를 그대로 사용한다. 현재 화면 연결은 솔로 보스 오른쪽 패널이다. 유니온 기록 조회는 같은 API에서 지원하지만 유니온 탭의 보스별 기록 패널은 아직 연결하지 않았다.

## 분석과 원문 보존

공통 decoder는 `tools/Phase3B2/BattleLogAnalysis/`에 있다. 알려진 schema 지문만 해석하고, bounded raw DEFLATE 해제와 참조 해소 후 CommonHurtEvent의 적용 피해를 사용한다. ProjectileSpawn의 소유 관계로 적 투사체를 구분하며, 아군 발사체의 피해는 소유 캐릭터로 귀속한다. 캐릭터 식별자가 유일하게 해소되고 개인 합계가 같은 보고서의 투사체 피해 총합과 일치할 때만 `ready`를 저장한다.

원본 게임 식별자는 decoder의 비공개 입력에만 있으며 DB 결과에는 관측 ordinal과 로컬 UID만 사용한다. 스키마 미지원·참조 결손·합계 불일치는 차감값을 만들지 않는다. 범용 스킬/효과 분석과 행동 시간표는 이번 구현에 포함하지 않는다.

새 통계 수집의 원문 저장 위치는 `C:/ProgramData/NikkeLocalLab/BattleLogs/{accountUid}/{battleUid}.private.bin`이다. 같은 폴더의 private JSON은 원문 hash, 전투 문맥, 해석용 캐릭터 식별 대응 및 분석 결과를 보존한다. 기존 최대 10건의 임시 진단 세션과 독립적이며, 건당 8MiB 상한은 유지한다. 압축 해제는 32MiB·200만 레코드로 제한한다. 폴더는 운영자/SYSTEM/Administrators의 비공개 ACL로 설치했다. 자동 삭제는 하지 않는다. 파일 저장 실패는 controlled 로그에 남기고 숫자 결과 처리를 중단하지 않는다.

현재 개인 투사체 분석은 결과 수신 시 제한된 decoder로 수행해 숫자 관측과 함께 영속화한다. 계획에 있는 별도 비동기 분석 worker·대용량 행동 인덱스는 아직 도입하지 않았다. 분석 실행 버전은 `projectile-damage/v1`이며 기존 분석 행을 임의 덮어쓰지 않는다. 재분석이 필요하면 새 규칙 버전으로 보존한다.

기존 진단 로그는 동일 전투 UID·계정·빌드와 로컬 캐릭터 식별 대응을 해소해 분석했다. 당시 TAB와 몬스터 보고서 합계를 운영 DB와 다시 대조한 후 별도 분석 테이블에만 입력했다. 현재 레벨·장비를 과거 전투에 대입하지 않았다. 원문이 보존되지 않은 과거 기록을 역산해 채우지는 않는다.

## 2026-09-20 초상화 표시 정정

최초 기록 화면은 캐릭터 관리 화면용 블라블라 MI(256×512) 세로 그림을 정사각형 영역에 중앙 crop하여 사용했다. 원본 파일 존재 검사만으로 얼굴 초상화의 시각 품질을 보장하지 못했다. 같은 크기의 브라우저 비교에서 블라블라 SI 얼굴 전용 정사각형 원본이 선명하게 표시되는 것을 확인했다.

`tools/AccountCollector/raid_portrait_assets.py`는 공개 캐릭터 이름·분류로 유일한 대응을 해소하고 SI PNG를 로컬 캐릭터 UUID 파일명으로 저장한다. 비공개 계정/세션 데이터는 사용하지 않는다. 202명 모두 정사각형 PNG와 hash를 검사하여 `editor/assets/character-faces/`에 설치했다. 기록 목록과 상세는 이 이미지를 우선 표시하며, 얼굴 파일이 없으면 기존 그림으로 fallback한다. 기존 캐릭터 관리용 세로 이미지는 유지한다. 향후 캐릭터가 추가되면 이 캐시 도구를 다시 실행해야 한다. 현행 캐릭터 동기화가 이 새 도구를 자동 실행하지는 않는다.

브라우저 동작 검사와 실제 그림의 42px 비교를 완료했다. 설치는 정적 이미지 202개와 `raid-records.js`만 교체했으며 DB/서버/실행 bundle은 변경하지 않았다. 기존 관리도구 창에는 JS가 이미 로드되어 있으므로 다시 열면 적용된다. 근거: Git 제외 `artifacts/raid-portrait-quality-20260920/`의 `render.png`, `receipt.json`, `installation.receipt.json`.
