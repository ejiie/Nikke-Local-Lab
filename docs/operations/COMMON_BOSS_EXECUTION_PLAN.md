# 보스 자동 추가와 공통 실행 경로 통합 계획

작성: 2026-09-14. 상태: **P0/P1 및 P2-1 완료, P2-2 읽기 조사·상세 설계 진행**.
운영자는 이 계획을 문서화하고 단계별로 해결하도록 지시했다. 이 문서는 해당 작업의
상세 순서와 완료 기준이다. 전체 작업 입구는 [안정화 계획](../STABILIZATION_PLAN.md)이다.

## 1. 사용자 요구와 완료 목표

UI에서 보스 추가를 요청하면 백엔드가 원본 근거로 패턴을 조립하고, 속성을 자유롭게
선택하도록 변환하며, 필요한 QTE와 FX를 조정한다. 준비된 전투 입력을 공통 실행기에
공급한다. 새 보스마다 에이전트가 전용 서버·스크립트·수동 전달 계획을 만드는 절차는
제품의 정상 흐름이 아니다. 근거 없는 패턴 생성이나 결손 데이터 추정도 하지 않는다.

같은 client build와 같은 실행 정책에서는 시즌별 전투 입력을 제외한 부팅·인증·음성·
프로세스 관리·종료 처리가 공통이어야 한다. 검증용 계정, 독립 저장 공간, 승인 상태는
같은 실행기의 입력/정책으로 표현한다. 원본 보호를 위한 별도 디렉터리는 허용되지만
그것을 이유로 시즌별 실행기나 다른 사용자 설정 정책을 만들지 않는다.

목표 흐름:

```text
UI 보스 추가 → 원본 분석 → 패턴/속성 조립 → 필요한 QTE/FX 변환
             → 참조·리소스·변경 범위 검증 → 공통 실행 구성 생성
             → 사용자 시작 → 공통 부팅/전투/종료·복구
```

자동 조립 완료, 실행 준비 완료, 사용자 실게임 인수는 별도 상태로 보존한다.
미해결 리소스나 변형은 정확한 단계/이유를 반환하며 완료로 승격하지 않는다.

## 2. 요구사항·구현·증거의 구분

- 현재 요구의 권위는 2026-09-14 운영자의 공통 경로/자동 조립 지시다.
- [원래 로드맵](../archive/FOLLOWUP_AUTOMATION_BOSS_ACCOUNT_ROADMAP.md)의 4.3절과
  공통 profile/변형기 설명은 설계 의도의 근거다. 과거의 특정 시즌 게시 제한이나
  당시 실행 지시를 이번 작업의 자동 실행 지시로 재사용하지 않는다.
- [보스 파이프라인](../features/BOSS_ONBOARDING_PIPELINE.md)은 재사용할 구현과 과거
  한계를 설명한다. 현재 코드가 그렇다는 사실만으로 새 제품 요구를 만들지 않는다.
- [기존 검사 정비 계획](VALIDATION_PREFLIGHT_PLAN.md)의 A/B 구현과 실패 증거는 보존한다.
  후속 우선순위는 본 계획이 대신한다. C의 빠른 검사 prototype은 공통 실행 계약을
  세운 뒤 평가하며, S29 별도 실행기를 더 확장하는 방향으로 이어가지 않는다.

확인된 사실: 일반 준비기는 profile v1/v2만 허용하지만 공통 변환기는 이미 v3를 읽는다.
v3 서버 해석 지원은 UserValidation 후보 빌드에만 연결돼 있다. 이 불연속은 제품의
시즌별 부팅 요구가 아니라 현재 통합의 결손이다. profile v3와 runner-input v3는
서로 다른 계약이며 숫자가 같다는 이유로 결합하지 않는다.

S26 일반 경로는 현재 음성 선택을 읽는다. S29 검증 경로는 준비 snapshot과 현재 값의
일치를 요구하고 고정된 음성 선택을 적용·복원한다. 과거 FX 실험에서 특정 언어 리소스가
결손이었던 사실은 해당 입력의 검증 근거이며 S29 고유 음성 정책의 근거가 아니다.
최근 S29는 음성 로딩 전 snapshot 검사에서 실패했고, 실패 시 선택은 정상 시작한 S26의
선택과 일치했다. 변경 프로세스는 미확정이다. 원시 값·SID를 문서에 기록하지 않는다.
로컬 비교 근거: `artifacts/validation-preflight-20260914/failure-investigation-1/`의
`S26-S29-COMPARISON.md`, `s26-comparison.json`, `FINDINGS.md`.

완료한다. 승인 범위 안의 구현마다 재승인을 요구하지 않는다. 요구 충돌이나 근거 없는

P1 설계의 출발점은 기존 `BossRuntimeVariantProfile`, `LaunchContext`, runner input이다.
입력의 책임은 선택 보스/계정 revision, 원본·파생 데이터 hash, 요청 약점, QTE/FX 변환,

소비자 호환 대조 후 확정한다. 설계 초안을 실행 지원 완료로 표시하지 않는다.

P1 결과는 [공통 입력·호환 계약](../contracts/COMMON_BOSS_EXECUTION.md)에 확정했다.
기존 wire v1/v2/v3를 재사용하고 공통 생성기에서 완전한 lifecycle/FX 입력을 검증한다.
교차 profile FX를 거절하며 호출 후 버전 덮어쓰기를 제거했다. 새 합성 69개(PS7/WinPS5),
실제 매핑 routing 4개, API focused 33개가 통과했다. v3 FX의 고정 역할과 특수 패턴의
속성 조건·실드 FX 표현은 아래 P2에서 정비한다. S29 운영 실행이나 통합 설치가 완료된
것은 아니다. QTE와 FX를 함께 검사하는 요구 자체를 제거하지 않는다.
병행한 공간 조사는 [프로젝트 용량 정리 후보](PROJECT_STORAGE_AUDIT_20260914.md)를 따른다.
후보 조사만 했으며 파일 삭제는 하지 않았다.
운영자의 후속 지시에 따라 P2~P6을 완료한 뒤 저장소 점검·정리·최적화를 수행한다.
그때 현재 참조와 복구 필요성을 다시 확인하며, 기존 후보 조사를 삭제 승인으로 해석하지 않는다.

버전별 파싱은 허용한다. 검증을 마친 의미 모델 이후에는 실제 QTE/FX 변환 유무로
처리를 선택한다. `season == 29`, `profile == v3`만으로 다른 부팅/음성/종료 정책을
고르는 구현은 수락하지 않는다. 모델이 표현하지 못하는 새 기능은 명시적 unresolved로
남기고 공통 지원을 보강한다. v3 표기를 낮추거나 과거 pin을 덮어써 통과시키지 않는다.

### P2 상세 계획 — 2026-09-14 운영자 요구 반영, P2-1 완료

**특정 속성 외 피해를 받지 않는 body·parts·QTE 등의 특수 패턴에는 예외 없이 속성
실드가 있으며, 속성 조건과 FX 조정을 함께 처리한다.** 이는 운영자가 명시한 도메인
요구다. 모든 원본 자산의 분석을 이미 마쳤다는 관측 주장이 아니다. 원본에서 필요한
조건이나 FX 연결을 찾지 못하면 결손으로 남기고 준비 완료를 거절한다.

앞서 제안한 'QTE만 / FX만 / 둘 다'를 독립적인 정상 완료 조합으로 사용하는 계획은
철회한다. 처리 단위는 특수 패턴에 연결된 대상·피해 허용 속성 조건·실드 FX다. QTE는
그 대상 중 하나이며, QTE가 없다는 이유로 body나 parts의 실드 처리를 생략하지 않는다.
실드가 없는 일반 패턴을 발견한 경우와 특수 패턴의 필수 증거가 결손인 경우도 구분한다.

원본 보스 속성만으로 FX 선택을 결정하지 않는다. 기존 필드를 다음처럼 함께 사용한다.

| 의미 | 기존 필드 | 사용 기준 |
| --- | --- | --- |
| 원본 보스 속성 (`boss.element`의 역할) | `sourceAffinity.bossElementCode` | 원본 값으로 보존; 별도 중복 필드 신설 없음 |
| 속성별 FX | `elementShield.fxVariants[].bossElementCode` | 선택 약점에서 계산한 실행 보스 속성에 대응하는 FX 확인 |
| FX 출처 | `elementShield.fxVariants[].mappings[].sourceKindCode` | `boss_specific` / `common` 구분; 보정 필요성을 출처만으로 단정하지 않음 |
| 실제 자산 근거 | `mappings[].assetBundles`, prefab 집합 hash | 대상 참조·자산 내용·형상과 연결 관계 검증 |
| 현재 추가 transform 계획 | `shieldFxTransformNormalization` | 검증 결과에서 생성; 기존 고정 목록을 일반 규칙으로 사용하지 않음 |

현재 S29 profile에서 전격과 수냉은 `boss_specific`, 작열·풍압·철갑은 `common`이다.
현재 normalization은 전격을 기준으로 작열·풍압·철갑만 추가 보정한다. 이 값들은
해당 profile의 관측이며, 모든 보스의 원본·보정 대상을 고정하는 근거가 아니다.

FX 조정은 필수 처리다. 선택 속성에 맞는 FX 선택·참조 연결·적합성 검증을 수행하고,
자산의 추가 transform 변경이 필요한지도 확인한다. 기존 전용 FX가 그대로 적합하다는
근거가 있으면 그 자산을 재사용할 수 있다. 이때 '추가 바이너리 변경 없음'은 FX 처리를
생략했다는 뜻이 아니다. 조건만 바꾸고 FX를 미확인 상태로 두는 완료는 허용하지 않는다.

| 순서 | 변경 범위 | 완료 기준 |
| --- | --- | --- |
| P2-1 (완료) | 원본 속성·선택 약점·속성별 FX 출처를 공통 입력으로 해석 | 원본 보존, 전격·수냉 전용 FX를 포함한 매핑 확인, 비전격 원본에도 같은 처리 |
| P2-2 (조사 진행) | body·parts·QTE의 속성 제한 패턴과 연결된 실드 조건·FX 분석/조립 | 대상별 조건과 FX를 함께 검증; 결손·대상 간 혼입 거절; 고정 전격/세 보정 대상 제거 |
| P2-3 | Python 조립기·C# 변환기·준비기·서버의 형식/의미 호환 정리 | 기존 봉인 profile 보존; 실제 표현 결손으로만 계약 확장 판단; QTE/FX 결합을 단순 제거하지 않음 |
| P2-4 | 일반 준비기의 완전한 profile 검증과 공통 서버 해석 지원 연결 | S26·S29·추가 후보가 같은 준비 함수와 서버 산출물 사용; 버전 gate 완화만으로 완료하지 않음 |
| P2-5 | 기존 파이프라인의 조립 결과를 공통 준비/전달에 연결 | profile·약점·조건/FX·변경/복구 근거 결박; 보스별 수동 서버 빌드/전달 계획 불필요 |
| P2-6 | 회귀 증거와 P3/P4 인계 기록 | 아래 행렬 및 필수 검사 통과; 준비·전달 완료와 실제 실행 가능 상태 구분 |

P2 검사는 S26/S29 실제 로컬 입력을 오프라인 대조하고 S34를 추가 후보로 확인한다.
비전격 원본과 다섯 선택 약점은 합성 검사로 보완하며 실제 원본 분석과 구분한다.
body·parts·QTE별로 조건+FX 일치, 적합한 기존 FX 재사용, 추가 transform 필요,
필수 조건/FX 결손, 잘못된 대상 연결/hash, 오래된 준비 결과 재사용을 검사한다.
실드 없음은 원본 근거가 있어야 한다. 시즌 숫자만 바꾼 fixture로 일반성을 주장하지 않는다.

P2는 공통 전투 입력의 준비·전달 통합까지다. 부팅·음성 정책은 P3, 실제 FX 적용·복구는
P4, UI 연결/퇴역은 P5, 설치·사용자 실게임 인수는 P6에서 완료한다. 필요한 FX 적용이나
공통 실행 지원이 미완료이면 P2 산출물 생성만으로 게임 실행 가능 상태로 올리지 않는다.

P2-1 구현: `Nll.PhaseDPreparation.ps1`의 `Resolve-PhaseDBossAffinity`가 기존 profile에서
원본 속성/약점, 선택 약점, 실행 보스 속성, 전체 FX 매핑, 원본/실행 대상 FX를 해석한다.
일반 준비기의 내부 `plan.affinity`로 전달하며 coordinator도 여기서 원본 속성을 읽는다.
기존 공개 projection·binding 및 실행 대상 FX 전달 필드는 유지한다. profile 수정이나
별도 `boss.element` 필드 신설은 없다. 모든 속성의 매핑/출처/자산 pin 형태를 확인하며,
실제 자산 적합성·전체 profile 의미 검증·변형 필요성 판정은 후속 단계 책임이다.

P2-1 검증: PS7/WinPS5에서 기존 준비기 16개와 새 합성 35개 사례가 통과했다. 새 사례는
다섯 원본 × 다섯 약점 25개, 순서가 다른 FX 목록과 혼합 출처 매핑 1개, 결손/잘못된
출처·자산 pin/원본 상성/실드 mode 거절 9개다. 실제 준비 경로와 해석 함수의 결과를
대조하고 입력 객체/파일이 보존되는지 확인했다. checked-in S29의 전격·수냉 전용 FX도
다섯 약점에서 오프라인 확인했다. S26 준비와 S29 기존 차단 상태는 유지하며, S29의
v3 준비/실행 허용·자산 변형·설치·게임 실행 완료를 뜻하지 않는다.

P2-2의 실제 원본 읽기 결과와 구체 순서는 [속성 제한 패턴 조사](P2_2_ELEMENT_SHIELD_INVESTIGATION.md)에
기록했다. S29 면역 함수 3개 중 하나는 FX 슬롯이 없고 나머지 둘이 같은 FX를 사용한다.
따라서 FX 필수성은 개별 함수가 아닌 특수 패턴 단위로 검사한다. 함수/QTE는 같은 모델의
몬스터 3개가 공유하며, 수냉 전용 FX도 파괴 연출 하위 rotation 1곳이 전격과 다르다.
QTE 자산의 실제 로딩 경로와 짧은 면역 함수의 표시/시간 연결, 하위 FX 차이의 보정 필요성은
미해결이다. 다음은 이 연결을 해소하는 읽기 조사이며 보정 코드·실행 허용은 아직 변경하지 않는다.

## 5. 회귀·설치·완료 기준

- S26/S29와 추가 보스 하나를 같은 요청·조립·준비·실행 경로로 처리한다. 추가 보스는
  기존 로드맵의 S34를 우선 오프라인 대조하며, 입력 결손이면 추정하거나 자동 게시하지 않는다.
- 다섯 약점과 body·parts·QTE별 속성 조건/실드 FX의 일치, 기존 FX 재사용/추가 변형,
  근거 있는 실드 없음, 결손·중복·잘못된 hash, 부팅 실패·중도 종료·재시도·복구 실패를
  검사한다. 다른 원본·패턴 입력으로도 같은 호출 경로인지 관측하는 검사로 검증한다.
- 일반 부팅 중 음성 설정 쓰기 0을 검증한다. 외부 변경/리소스 결손은 숨기지 않는다.
- UI 보스 추가 후 수작업 전용 서버 빌드·전달 계획 작성·설정 수정이 필요하면 미완료다.
- 저장소가 요구하는 repository/Phase 0/완료 Phase/Phase 3B/Actions 검사를 작업 전후
  실행한다. 해당 코드 변경에는 의미 있는 focused 검사와 필요한 격리 PG 검사를 더한다.
  자동 검사 통과를 original-runtime/FX 렌더링 인수로 승격하지 않는다.
- 검증된 v6와 원본은 복구 기준으로 보존하고 새 공통 구성은 별도로 준비한다. 통합 전
  기존 S26을 무작정 재설치하거나 새 전체 client를 복제하지 않는다. 설치 시 파일/포인터
  변경 목록과 rollback을 먼저 구체화한다. 기존 미완료 실행의 복구 도구는 제거하지 않는다.
- 게임은 운영자가 직접 실행한다. 이미 인수한 S26의 재인수를 반복 요구하지 않는다.
  공통 실행기 변경으로 필요한 새 검증은 영향과 근거를 구분해 제시한다. 승인된 관리자
  진단·구현은 에이전트가 수행한다. 공식 설치본·운영 DB·승인 DLL 변경으로 확대하지 않는다.
- 빠른 검사 최적화는 이 통합 이후 수행한다. 전체 경로에서 측정하지 않은 수초 시작이나
  캐시된 성공값을 근거로 검사를 건너뛰는 방식은 완료로 인정하지 않는다.

## 6. 에이전트 작업 기준과 사용자가 확인할 항목

요구사항을 지키는 책임은 에이전트에게 있다. 사용자에게 모든 파일/코드 검토를 맡기지
않는다. 문서 분량을 늘리는 것보다 짧은 불변 조건과 검증 가능한 완료 기준을 유지한다.

1. 변경 이유를 **사용자 요구 / 확인한 코드·관측 / 아직 가정**으로 구분한다. 기존 구현을
   요구사항으로 승격하거나 편의상 추가한 조건을 필수 조건이라고 설명하지 않는다.
2. 수정 전에 기존 정상 경로와 재사용 지점을 확인한다. 전용 경로나 새 추상화를 추가하면
   필요한 이유, 공통 처리로 해결할 수 없는 근거, 이관/퇴역 조건을 제시한다.
3. 관련 없는 설정을 바꿔 실패를 통과시키지 않는다. 실제 변경 파일·설정·범위와 복구를
   증거로 남긴다. 보호 경계나 승인 문구를 편의상 재해석하지 않는다.
4. 테스트 통과만 보고하지 않는다. 사용자 흐름의 성공/실패 예시와 일반성 증거를 보고하고,
   구현/자동 검사/설치/사용자 실게임의 완료 상태를 구분한다.
5. 작업 상태는 본 표 한 곳에서 갱신한다. 과거 문서는 상위 안내만 연결하고 실패 기록은
   보존한다. 같은 장애에서 증거 없이 반복하면 접근을 재검토하며 예외 조건을 쌓지 않는다.

다음 작업에 사용할 짧은 요청 예시:

> 이 계획의 다음 미완료 단계를 수행해 주세요. 기존 공통 경로를 재사용하고, 요구사항·
> 관측 사실·가정을 구분해 주세요. 시즌별 실행 예외와 무관한 설정 변경을 추가하지 말고,
> 두 번째 보스에도 같은 경로가 적용되는 증거를 남겨 주세요. 완료한 것과 남은 것을
> 구분해 문서를 갱신하고, 이미 승인한 작업은 계속 진행해 주세요.

지속 적용할 핵심 기준과 이 계획의 링크는 루트 AGENTS.md에 둔다. Codex가 프로젝트
지침을 읽는 방식은 [공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를
참고한다. 지침만으로 오류를 보장해서 막을 수 없으므로 계약 검사와 변경 검토를 병행한다.
