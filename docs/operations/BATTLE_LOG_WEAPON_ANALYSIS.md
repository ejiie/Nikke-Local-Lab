# BattleLog 사거리·무기 교체·샷건 조사

라피의 정적 경로도 후속 [실전 관측](BATTLE_LOG_RAPI_WEAPON_OBSERVATION.md)에서 101회 연결했다. 기본 무기 복귀 뒤의 피해는 발사체 원천 참조로 추적하며, 교체 시 ammoDelta를 발사 수로 환산하지 않는다. 아래의 라피 실전 미검증 표기는 이 후속 관측 이전 상태다.

후속 실전 관측: [울트라 교체 무기·관통·샷건](BATTLE_LOG_ULTRA_WEAPON_OBSERVATION.md). 운영자가 이후 지정한 전투에서 스노우 화이트 7회·28타격, 맥스웰 6회·13타격, 츠바이의 실제 교체 및 샷건 코어 혼재를 확인했다. 아래의 ‘기존 표본에는 실제 교체/SG 없음’은 최초 표본에 대한 설명이다. 관통 피해의 계산/적용 연결은 단순 역순으로 일반화하지 않는다.

2026-09-19. 운영자가 지정한 두 GitHub 저장소와 로컬 152 정적 테이블, 이미 해석한 기존 전투 한 개를 대조했다. 새 다단히트 전투는 운영자가 분석을 요청한 뒤 읽는다. 조준·위치·모션 재구성은 요청 범위에서 제외한다.

전체 필드는 [BattleLog 해설](BATTLE_LOG_GUIDE.md), 이전 확정/미확정은 [확정 감사](BATTLE_LOG_CERTAINTY_AUDIT.md)를 따른다. 이 문서는 분석 결과이며 설치·DB·수집 설정 변경은 없다.

## 사거리 구간과 보너스

[ProperDistanceTable.cs](https://github.com/ejiie/Nikke-Dmg-Simulator/blob/c10395cc6c46caaea2c58c13d400796549a7eb17/SimulatorEngine/Nikke.Simulator.Core/Combat/ProperDistanceTable.cs)는 다음 기본 구간과 보너스 0.3을 정의한다. 원본 값의 단위 그대로이며 미터라고 새로 단정하지 않는다.

| 무기 | 기본 적정 구간 | 참고 구현의 구간 내 보너스 |
|---|---|---|
| SG | 0–25 | +0.3 |
| SMG | 15–35 | +0.3 |
| AR | 25–45 | +0.3 |
| MG | 35–55 | +0.3 |
| SR | 45–100 | +0.3 |
| RL | 0–0 | 기본 적정 거리 보너스 없음 |

양 끝을 포함하는 판정은 해당 참고 구현의 계약이다. 원본 로그로 정확히 경계 거리에 선 타격까지 검증한 것은 아니다.

로컬 CharacterTable의 BonusrangeMin/Max를 기본 ShotId의 WeaponType과 대조하면 위 기본 구간을 확인할 수 있다. 다만 **SR의 25–45 예외 설정 1개, SMG의 25–45 예외 설정 1개**도 있다. 여기서 설정 개수는 `(무기, ShotId, 최소, 최대)` 중복을 제거한 수이며 캐릭터 수로 환산하지 않는다.

[Nikke-Simul의 HitCalculator](https://github.com/ejiie/Nikke-Simul/blob/e9d7410a92a8b38619c0a8c4fe4f4f4c5133d004/src/Nikke.Core/Combat/HitCalculator.cs)도 DistanceBonus 기본값 0.3을 사용하지만 적정 거리 여부는 입력 조건으로 받는다. 두 저장소가 모두 실시간 거리를 자체 복원하는 것은 아니다.

기존 BattleLog에서는 사거리 계수가 1 또는 약 1.3이고, 같은 틱에서 연결된 30,563건의 isValidRange 판정과 중립/비중립 여부가 맞았다. **최종 피해를 무조건 ×1.3 한다는 뜻은 아니다.** 사거리 초과분 +0.3은 현재 재현 후보식에서 크리·코어·풀 버스트 초과분과 더하는 항이다.

로컬 원본에는 다음 효과 정의도 실제로 존재한다.

- StatBonusRangeMin / StatBonusRangeMax: 구간 변경 관련 효과.
- BonusRangeDamageChange / OutBonusRangeDamageChange: 구간 내/외 피해 변경 관련 효과.

따라서 통계에는 원본 `isValidRange`와 실제 계산의 `bonusRangeRateBits`를 우선 사용하고, 캐릭터별 기본 구간은 설명용 메타데이터로 연결한다. 무기 타입의 기본표로 실제 판정이나 실제 계수를 덮어쓰지 않는다. 무기 교체 후 구간이 어떻게 바뀌는지는 교체 이벤트와 효과 변경을 함께 보아야 하며, 교체된 무기 타입의 기본표를 자동 적용하지 않는다.

## 무기 교체 후 사격의 분류

로컬 CharacterSkillTable의 `SkillType=ChangeWeapon`인 280개 **스킬 행**을 확인했다. 레벨별 행을 포함하므로 캐릭터 280명 또는 교체 종류 280개라는 뜻은 아니다.

- 280행 모두 SkillValueData의 세 번째 값이 유효한 CharacterShotTable 행에 연결된다.
- 첫 번째 값은 Percent, 두 번째·세 번째는 Integer다.
- 지속 조건은 TimeSec 140행, Shots 130행, Battles 10행이다. 모든 교체 무기를 고정 시간으로 종료시키면 안 된다.
- ChangeWeaponEnd·ChangeWeaponMaxAmmo 효과 정의도 존재한다. 나머지 SkillValueData 항들의 전체 의미까지 확인한 것은 아니다.

[Nikke-Simul의 교체 처리](https://github.com/ejiie/Nikke-Simul/blob/e9d7410a92a8b38619c0a8c4fe4f4f4c5133d004/src/Nikke.Engine/Skills/SkillReplay.cs#L472)는 계수·발사 속도·교체 ShotId를 모드에 보관한다. [피해 기록](https://github.com/ejiie/Nikke-Simul/blob/e9d7410a92a8b38619c0a8c4fe4f4c5133d004/src/Nikke.Engine/Skills/SkillReplay.cs#L577)은 사격 형태의 피해로 처리하면서도 이를 만든 스킬과 교체 ShotId를 함께 유지한다. 해당 구현은 일부 교체 무기 사례를 다루는 참고이며 모든 원본 교체 조건의 완성된 구현으로 간주하지 않는다.

원본 로그를 분석할 때도 다음 두 축을 동시에 보존하는 것이 적절하다.

| 축 | 예시 / 근거 |
|---|---|
| 피해가 발생한 방식 | 사격 설정 / 캐릭터 스킬 직접 피해 / Function 효과 피해 — sourceKind/sourceId |
| 그 방식을 활성화한 출처 | 기본 무기 / 스킬로 교체된 무기 / 아직 미확정 — 기본 ShotId, ChangeWeapon, 스킬 참조 |

즉 **‘스킬에서 나온 교체 무기의 사격’은 스킬과 사격의 속성을 함께 가진다.** 한쪽 통계에서 제거하거나 두 군데 피해량을 더해 중복 집계하지 않는다. `sourceKind=0`만으로 기본 평타로 확정하지 않는다.

연결 순서는 다음과 같다.

1. 캐릭터 기본 ShotId를 읽는다.
2. ChangeWeapon의 fromShotId/toShotId와 시점을 보존한다. 두 값이 같으면 실제 전환으로 세지 않는다.
3. 각 사격 계산의 HitContextShape.sourceId를 발사 설정과 연결한다. 이 ID는 **발사 설정 ID이지 개별 발사 1회의 ID가 아니다.**
4. 사용한 교체 스킬의 대상 ShotId와 맞는지 대조한다. 복수 후보이면 시간상 가장 가깝다는 이유만으로 하나를 확정하지 않는다.
5. 전환 이후 도착한 이전 무기의 지연 피해가 가능하므로, 피해 발생 시점의 현재 무기만으로 분류를 덮어쓰지 않는다.

### 기존 실전에서 실제 확인한 범위

이전 표본의 ChangeWeapon 5건은 **모두 전투 종료 시점 180,146ms에 fromShotId=toShotId=기본 ShotId**로 기록됐다. 실제 전투 중 무기 전환의 증거가 아니다. 캐릭터 발사 원천 계산 30,079건은 모두 각 캐릭터 기본 ShotId와 연결됐다.

따라서 출처를 구분할 필드와 정적 연결은 확보했지만, 실제 교체 전후의 피해 귀속까지 검증했다고 주장하지 않는다. 운영자가 새 전투 분석을 요청할 때 해당 사례가 있으면 이 경로로 대조한다.

## 라피: 레드 후드 — 버스트 이외의 무기 교체 경로

2026-09-19 운영자는 발사 수 조건으로 교체되는 라피: 레드 후드도 다루도록 요청했다. 로컬 Locale_Character의 이름과 CharacterTable을 연결하고, 10레벨 StateEffect/CharacterSkill/Function 연결을 정적으로 추적했다. 새 실전 로그는 읽지 않았다.

```text
스킬 2의 StateEffect
  → Function: OnUseAmmo, TimingTriggerValue=120
  → UseCharacterSkillId
  → CharacterSkill: ChangeWeapon
  → DurationType=Shots, DurationValue=1
```

즉 이 정의는 **탄약 사용 조건이 호출하는 1발 제한의 교체 무기**다. 버스트 1회 사용이 있어야만 교체 출처를 찾는 분석은 이 경로를 놓친다. 기본 트리거 값 120은 현재 시점의 실제 발사 횟수를 로그에서 검증한 결과가 아니다. 버스트 쪽에는 TimingTriggerValueChange도 있으므로 조건값이 고정이라는 가정도 피한다.

추적 구조는 `기본 스킬2 → 조건/효과 → 호출된 추가 스킬 → 교체 발사 설정 → 피해`로 보존한다. 이 출처는 ‘본인이 버스트를 사용한 풀 버스트인가’와 독립이다. 실제 ChangeWeapon/UseCharacterSkill/피해 기록과의 연결, 조건 카운터 초기화·변경 시점 및 교체 종료는 실전 검증 전이다. 탄약 변화 한 건을 한 발로 세거나 교체 전후에 도착한 지연 피해의 출처를 덮어쓰지 않는다.

원본 정적 근거는 Git 제외 `rapi-chain.private.json`에 보존했다. 패시브는 CharacterSkillTable뿐 아니라 StateEffectTable의 효과 목록까지 따라가야 한다. 이름 매핑과 31개 연결 노드를 확인했으며, 이것은 통계 분석기 구현/설치 완료의 주장이 아니다.

## 샷건: 설정은 확인, 실제 펠릿 기록 방식은 대기

로컬 CharacterShotTable의 SG 설정은 총 33행이다. 그중 캐릭터 기본 ShotId에서 참조하는 서로 다른 설정은 28개다.

| 범위 | ShotCount × MuzzleCount | 설정 수 |
|---|---|---:|
| 캐릭터 기본 SG | 10 × 1 | 27 |
| 캐릭터 기본 SG | 5 × 2 | 1 |
| 기본 설정 외까지 포함 | 위 조합 외 3 × 1, 15 × 1도 존재 | 전체 33행 중 각 1 |

3 × 1 설정은 CenterShotCount=1이기도 하다. 중앙탄 수가 ShotCount에 포함되는지 별도로 더해지는지까지 이번 조사에서 확정하지 않았다. 위 표는 **설정 필드 값**이며 실제 적중 펠릿 수가 아니다.

추가로 확보한 필드/효과:

- ShotCount, MuzzleCount, CenterShotCount, MultiTargetCount, Penetration.
- 수동·자동 명중원 시작/종료값, 발사 시/명중 시 효과 목록.
- StatShotCount, StatAccuracyCircle 효과 정의. 기본 펠릿 수나 명중원 값이 전투 내내 고정이라는 가정은 피해야 한다.

두 참고 저장소의 샷건 가정은 다르다.

| 구현 | 실제 의미 / 한계 |
|---|---|
| [Nikke-Dmg-Simulator AccuracyModel](https://github.com/ejiie/Nikke-Dmg-Simulator/blob/c10395cc6c46caaea2c58c13d400796549a7eb17/SimulatorEngine/Nikke.Simulator.Core/Combat/AccuracyModel.cs) | 명중원/몸체/코어 면적 비율로 확률을 계산하는 모델. 대상 크기는 설정값이고 수축도 근사. 실제 원본 로그의 빗나간 펠릿 기록을 증명하지 않음 |
| [Nikke-Simul WeaponReplay](https://github.com/ejiie/Nikke-Simul/blob/e9d7410a92a8b38619c0a8c4fe4f4f4c5133d004/src/Nikke.Engine/WeaponReplay.cs#L102) | ShotCount×MuzzleCount 반복. 전 펠릿이 한 대상에 명중한다고 명시하며 코어 판정은 입력값. 실제 명중률 관측 자료가 아님 |

기존 원본 BattleLog의 62종·240필드에서 명시적 PelletIndex·Miss·ShotTraceId 필드는 찾지 못했다. 다른 필드에 해당 정보가 암묵적으로 표현될 가능성까지 배제하는 결론은 아니다. 현재 실전 편성에는 SG가 없으므로 다음은 남아 있다.

- 피해 사건이 펠릿별인지 합쳐진 기록인지.
- 한 번 발사에 속한 펠릿을 유일하게 묶을 수 있는지.
- 피해를 못 준 펠릿이 따로 기록되는지.
- 실제 발사된 전체 펠릿 수를 버프·무기 교체·특수탄까지 포함해 알 수 있는지.
- 관통·다중 대상·추가 피해가 명중 사건 수를 늘리는 경우의 구분.

조준·위치·모션 복원 없이도 로그의 명중 판정과 출처를 조사할 수 있다. 다만 기록에 없는 빗나감을 명중원 확률 모델로 만들어 실제 관측값처럼 제시하면 안 된다. SG 실전 자료를 해석하기 전에는 ‘펠릿 단위 완전 지원’으로 표시하지 않는다.

## 통계 작업에 유지할 요구

운영자는 이전에 제안한 시간대별 딜, 대상별 딜, 타격 판정 분포, 효과 유지 구간, 재장전, 버스트 운영, 회복 효율, 면역 손실을 모두 유용한 데이터로 수락했다. 구체적인 UI 배치는 아직 정하지 않았다.

- 전탄 대비 명중률과 **기록된 명중 중 코어/크리 비율**은 다른 지표다.
- 사거리 설명에는 캐릭터별 기본 구간을 쓰고, 실제 타격 통계에는 원본 판정/계수를 쓴다.
- 교체 무기 사격은 사격 방식과 스킬 출처를 함께 보존한다.
- 다단히트 새 전투는 운영자가 ‘분석하라’고 알린 뒤 처리한다.
- 전체 조준·위치·모션은 분석/통계 UI 요구에 넣지 않는다.

## 캐릭터별 버스트 참여 구간 — 운영자 추가 요구

운영자는 타격에 기록된 사거리 판정·계수를 우선하는 원칙에 동의했고, 교체 무기를 활성화한 스킬 출처도 보존하기를 원했다. 추가로 **풀 버스트 구간을 각 캐릭터의 본인 버스트 사용 여부에 따라 나누는 통계**를 요청했다. 다음은 분석 설계이며 DB/UI 구현 완료를 뜻하지 않는다.

### 전투 구간과 캐릭터 참여를 분리

| 전투 구간 | 캐릭터별 분류 |
|---|---|
| 버스트 충전 구간 | 비풀버스트·충전 중 |
| 충전 완료 후 선택·버스트 연계 구간 | 비풀버스트·선택/연계 중 |
| 풀 버스트 구간 | 해당 연계에서 본인 버스트 사용 / 본인 미사용 / 참여 여부 미확정 |

표시에서는 필요하면 비풀버스트를 묶을 수 있지만, 원자료에서 충전 대기와 스킬 선택·연계 시간을 합쳐 버리지 않는다. 충전 시작부터 게이지 준비까지와, 준비부터 풀 버스트 진입까지를 별도로 계산할 수 있어야 한다.

### 본인 버스트 사용 여부의 기준

- 각 풀 버스트 구간에 대응하는 직전 버스트 연계의 참여 캐릭터 집합을 만든다. 마지막 III단계 사용자만 참여자로 세지 않고 I·II·III단계 전체를 포함한다.
- 기존에 확인한 BurstChange.useChar와 UseCharacterSkill을 연결한다. 사용 기록과 단계 전환이 같은 틱이라고 가정하지 않는다. 기존 표본의 시차 68~86ms를 모든 캐릭터의 고정 허용오차로 만들지도 않는다.
- 단계 재진입·같은 캐릭터의 반복 사용이 있으면 해당 연계의 모든 사용 기록과 횟수를 보존한다. 단순히 3명 또는 정확히 3회여야 한다고 제한하지 않는다. 이런 특수 연계의 실전 대응은 별도 검증 대상이다.
- 참여 캐릭터에는 그 풀 버스트 전체를 ‘본인 사용’으로, 나머지에는 ‘본인 미사용’으로 분류한다. 충분한 연계 기록이 없으면 false 대신 미확정으로 남긴다.
- 풀 버스트 없이 끝난 연계는 별도 기록으로 유지하며 가상의 풀 버스트 구간을 만들지 않는다.
- 실제 풀 버스트 시작/종료 이벤트로 구간을 정한다. 설정상 duration을 고정 10초로 치환하지 않는다. 마지막 구간이 잘렸으면 관측 종료까지의 길이와 잘림 상태를 함께 보존한다.

### 구간별로 얻을 통계

각 캐릭터에 대해 구간 종류별 횟수·총 시간·피해량·DPS·타격 판정 비율을 비교할 수 있도록 한다. 총 DPS는 `해당 구간 피해 합 / 해당 구간 시간 합`으로 계산하고, 개별 구간 DPS의 단순 평균과 구분한다. 분모가 0이거나 시간이 미확정이면 DPS를 0으로 만들어 넣지 않는다.

특히 ‘본인 사용 풀 버스트’와 ‘본인 미사용 풀 버스트’의 피해/DPS를 나란히 비교하면 교대 버스트 딜러의 실제 기여 양상을 볼 수 있다. 보스 상태·동료 버프·크리·코어·사거리 조건도 달라질 수 있으므로 두 집계의 차이를 본인 버스트만의 순수 증가분이라고 해석하지 않는다.

**피해 발생 구간과 피해를 만든 스킬 출처는 독립 축**으로 보존한다. 이전 연계에서 만든 지속/지연 피해가 다음 구간에 들어와도 출처를 현재 연계로 바꾸지 않는다. 동일 틱 경계는 기록 순서를 보존하되 계산 계수의 풀 버스트 여부와 자동으로 같다고 주장하지 않는다. 이벤트별 상태와 계산 입력의 차이가 있으면 별도 표시한다.
