## 작업 방식

- 게임 실행과 화면·전투 판정은 운영자가 하고, 구현·오프라인/자동 검사·검증용 설치·CI/병합은 에이전트가 합니다(2026-09-13 지시).
- 구현, 자동 검사, 설치, 운영자 실게임 확인은 각각 따로 기록합니다. 준비 `ready`나 완료 팝업을 전투 인수로 올리지 않습니다.
- 같은 장애에서 약 30분간 진전이 없으면 반복 실험을 멈추고 원인·대안·범위 변경을 검토합니다.
- 검증된 Epinel DLL·실행 조합을 불필요하게 바꾸지 않습니다. 기존 진행도와 약점 없는 과거 기록(`unresolved`)을 보존합니다.

## 로컬 검사 환경 메모

필수 gate는 PowerShell 7(`pwsh`), Node.js(Phase 2A2의 editor 검사), Python, .NET SDK 8.0.407(`global.json`)을 PATH에서 찾습니다.
2026-09-27 세션에서는 시스템 PATH에 `pwsh`·`node`가 없어 Codex 런타임에 포함된 실행 파일을 PATH 앞에 넣고 실행했습니다.
이전 기록의 `NU1900`(NuGet 취약성 조회 네트워크 실패)은 네트워크가 되는 이번 실행에서 재현되지 않았습니다. repository 검사는
`origin`이 있는 checkout이므로 `-AllowRemote`를 붙여야 통과합니다(`scripts/verify-repository.ps1`). 이전 기록의 "origin 정책
충돌"은 이 옵션 없이 실행한 결과입니다.
명령과 CI 구성은 [GitHub 자동화](operations/GITHUB_AUTOMATION.md)를 따릅니다.
