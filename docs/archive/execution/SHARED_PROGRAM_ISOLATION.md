# 공식 프로그램 차단의 실행 수명주기

> 2026-09-27 보관: 작성 당시의 기록이며 현재 작업 지시가 아닙니다. 현행 문서는 [문서 색인](../../README.md)에서 찾습니다.

2026-09-17 사용자 요청: 공식 로그인 차단을 해제하고 로컬 게임 실행 중에만 차단한다.

## 관측과 원인

`NLL PhaseD 151 Client Isolation` 그룹의 22개 규칙 중 15개는 공식 `C:\NIKKE`
프로그램, 1개는 공유 `AntiCheatExpert Protection` 서비스, 6개는 로컬 복제본이다.
151 설치 코드가 이들을 모두 상시 활성화하여 공식 런처 로그인도 차단했다.
공식 경로 15개는 사용자 지시에 따라 먼저 비활성화했다.

## 구현

- 관리도구 시작·준비 조회는 공유 프로그램 차단을 활성화하지 않는다.
- `Read-PdRuntimeBundle`은 규칙의 대상/방향/동작과 복제본 차단을 확인한다.
  공식 프로그램·공유 ACE 규칙은 유휴 시 비활성 상태를 허용한다.
- 공통 실행기는 실행별 Job 생성 후, 첫 게임 시작 자식 프로세스를 만들기 전에
  `Enter-PhaseDSharedIsolation`을 호출한다. 시즌이나 보스에 따른 분기는 없다.
- 시작 전 프로세스/서비스 종료를 확인하고 규칙 상태와 서비스 신원을
  `shared-isolation.before.json`에 먼저 기록한다. 그 후 공유 규칙을 일괄 활성화하고 검증한다.
  일부만 활성화된 실패도 같은 기록으로 복구한다.
- 정상 종료·시작 실패·고아 실행 복구가 사용하는 두 물리 정리 checkpoint 함수에서
  `Restore-PhaseDSharedIsolation`을 호출한다. 실행 Job의 실제 프로세스 0 증명을 유지하고,
  FX/DB/hosts 복구 후 공유 서비스·관련 프로세스의 종료를 확인한 뒤 이전 활성 상태로 복원한다.
- 실행 전 중지되어 있던 정확한 공유 ACE 서비스만 경로·파일 해시·시작 유형을 대조하여
  정상 SCM 중지를 요청한다. 서비스 시작 유형이나 드라이버는 이 변경에서 수정하지 않는다.
- 종료 증명이나 복구에 실패하면 차단을 유지하고 기존 비종결 실행 복구 경로로 남긴다.
  이미 원복한 재시도는 완료 기록과 규칙 상태만 확인하여 이후 공식 세션을 중지하지 않는다.
- 로컬 복제본의 영구 차단은 유지한다. 설치 코드도 공유 규칙은 비활성 상태로 만든다.

`Nll.PhaseDSharedIsolation.ps1`은 새 실행의 코드 묶음에 해시로 고정한다.
과거 코드 묶음에 이 helper가 없는 경우도 읽고 해당 실행에 보존된 복구 코드로 전달한다.
현재 설치본은 저장소의 공통 실행기를 직접 사용하므로 API 재빌드가 필요하지 않다.
