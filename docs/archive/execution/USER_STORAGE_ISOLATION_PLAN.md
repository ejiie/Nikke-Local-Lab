# 공식 클라이언트와 NLL 사용자 저장소 격리 계획

> 2026-09-27 보관: 작성 당시의 기록이며 현재 작업 지시가 아닙니다. 현행 문서는 [문서 색인](../../README.md)에서 찾습니다.

갱신: 2026-09-17. 상태: **운영 방향 확정, 별도 계정에서 공식 실행 확인 전**.
여기서 저장소는 LocalLow·사용자 레지스트리·캐시 등 사용자 상태를 뜻한다.

## 확정한 방향

운영자는 현재 Windows 프로필 전체가 이 프로젝트 전용임을 확인하고,
공식 게임은 다른 Windows 계정에서 실행하기로 결정했다.
따라서 **NLL은 현재 `nlloperator`에 유지하고, 공식 게임 사용자를 분리한다.**

앞서 제안한 NLL 전용 계정 신설·실행 트리 이전·DB/DPAPI 비밀 이전·교차 사용자 실행기 구현은
이 결정으로 대체한다. 해당 이전 작업은 착수하지 않았고 현재 계획에 필요하지 않다.

| 영역 | 운영 기준 |
|---|---|
| 현재 `nlloperator` 프로필 | NLL 개발·관리도구·로컬 게임 실행 전용으로 유지 |
| 별도 Windows 계정 프로필 | 공식 런처 로그인과 공식 게임 실행에 사용. 계정 이름/SID 및 실행 확인은 아직 기록되지 않음 |
| `C:\NLL` 및 프로젝트 저장소 | 현재 경로·DB·설정·암호화 비밀·실행 복제본 유지 |
| 공식 `C:\NIKKE` | 공식 런처가 소유하는 설치/업데이트 경로. NLL은 승인된 동기화 입력을 읽기만 함 |
| hosts·방화벽·공유 ACE·HKLM·ProgramData | 같은 PC의 공용 영역. Windows 계정 분리 후에도 기존 수명주기 관리 필요 |

## 확인된 사실과 미확인 사항

- 문제를 관찰한 당시 공식 클라이언트와 NLL 복제본은 같은 Windows 사용자로 실행됐다.
- 해당 사용자 아래 `AppData\LocalLow\com.proximabeta\NIKKE`,
  `AppData\LocalLow\com_proximabeta\NIKKE`와 `HKCU\Software\com.proximabeta\NIKKE`가 존재한다.
  두 LocalLow 경로는 별개이므로 합치거나 일괄 삭제하지 않는다.
- bootstrap은 별도 사용자 토큰을 지정하지 않는다. 음성 preflight와 Player.log 수집도
  현재 사용자 저장소를 참조한다. NLL을 현재 전용 프로필에 유지하면 이 경로를 이전할 필요가 없다.
- 공식 서버 선택 화면의 Global 계정 존재 표시를 결정하는 정확한 파일·키·응답은 미확인이다.
  공식 서버에 계정이나 진행 정보가 생성·전송됐다는 증거도 없다.
- 별도 계정에서 같은 표시가 나타나는지는 아직 확인하지 않았다.
  계정 분리만으로 기존 표시의 원인이나 소멸을 확정하지 않는다.

Unity의 Windows 사용자별 저장 경로는
[persistentDataPath](https://docs.unity3d.com/ScriptReference/Application-persistentDataPath.html)와
[PlayerPrefs](https://docs.unity3d.com/ScriptReference/PlayerPrefs.html) 문서를 참고한다.
관리자 권한이나 SYSTEM 서비스의 접근까지 막는 보안 샌드박스로 해석하지 않는다.

## 운영 및 확인 순서

1. **NLL 종료·복구 완료 후 계정 전환**
   로컬 게임과 관리도구의 종료 처리가 완료되고 공유 프로그램 차단/hosts 복구가 끝난 뒤
   공식용 Windows 계정으로 전환한다. 빠른 사용자 전환은 기존 프로세스를 종료하지 않으므로
   공식 게임과 NLL 게임을 동시에 실행하지 않는다.
2. **공식용 계정에서 정상 로그인·실행**
   해당 계정으로 Windows에 로그인하고 공식 런처를 실행한다.
   NLL 계정의 LocalLow·레지스트리·INTL 인증 캐시를 복사하지 않는다.
   공식 로그인은 운영자가 직접 수행하며 도구는 자격 증명·세션·토큰을 수집하지 않는다.
3. **사용자 저장소 분리 확인**
   공식 게임의 실제 프로세스 사용자와 LocalLow/로그 생성 위치가 공식용 프로필인지 확인한다.
   NLL은 기존 프로필에 기록되는지 확인한다. 머신 공용 캐시는 사용자별 캐시와 구분한다.
   새 프로필에서 필요한 정상 리소스 다운로드가 있을 수 있으며 현재 캐시를 공유하는 링크로 우회하지 않는다.
4. **최소 기능 확인**
   공식용 계정에서 서버 선택 표시·언어·정상 실행을 확인한다.
   필요하면 공식 종료 → NLL 실행/종료 → 공식 재실행으로 교차 영향을 확인한다.
   Global 표시가 계속되면 별도 원인 조사로 다루고 프로필 전체 삭제로 해결하지 않는다.

완료 조건은 실제 사용자/저장 위치 분리 및 순차 실행 시 상호 영향 없음이다.
운영 방향 확정과 실제 실행 확인은 구분하여 기록한다.

## 변경 범위와 보존

- 이 결정만으로 새 Windows 계정을 만들거나 NLL 코드를 변경하지 않는다.
- NLL DB·계정·육성 revision·DPAPI 비밀·ACL 이전은 하지 않는다.
- 기존 프로젝트 프로필에 남은 공식 로그인/실행 흔적의 정리는 별도 요청과 정확한 항목 식별 후 검토한다.
- 매 실행 전체 LocalLow 또는 대용량 자원 검산을 추가하지 않는다.
- 공식 설치 업데이트와 NLL 실행도 겹치지 않도록 운영한다. 공식 설치본의 변화는 기존 동기화 절차로 읽는다.
- 머신 공용 차단과 복구는 [공유 프로그램 격리](SHARED_PROGRAM_ISOLATION.md)를 따른다.

이번 변경은 문서에만 반영했으며 Windows 계정·사용자 설정·DB·설치 파일은 변경하지 않았다.
