## 2026-09-20 효과별 보기와 강화 평타 — v3

피해 값이 정확히 0인 효과와 강화 상태 구간은 요약·효과별 보기 모두에서 숨긴다. 비율이 작아 표시상 0%가 된 양수 피해는 숨기지 않는다. 원문과 분석 캐시는 보존하며 화면의 피해 합계는 바뀌지 않는다. 라피 표본의 `InstantNumber` 0 피해 적용 7건을 숨겨도 별도 `Damage` 7건의 792,424,173과 전체 6,714,406,392가 유지됨을 설치된 UI로 확인했다. 비공개 적용 기록: `artifacts/damage-zero-hidden-20260920/installation.receipt.json`.

체크박스는 **상단 비중 막대에도 적용**한다. 해제하면 평타·스킬 직접 피해 등의 상위 분류를, 체크하면 하위 효과 각각을 다른 색으로 나누고 막대 아래에 이름과 전체 피해 대비 비율을 표시한다. 작은 구간도 비율을 읽을 수 있도록 범례를 사용한다. 일레그 표본은 일반 평타 58.64%, 스킬 2 3.63%, 버스트 37.71%로 표시된다. 각 비율은 전체 캐릭터 피해 기준이며 스킬 직접 피해 내부의 비율이 아니다. 수로시의 일반·80·160펠릿 구간도 같은 방식으로 막대를 분리한다. 화면 파일 두 개만 백업 후 설치했고 실제 API 응답 화면·전환·390px 폭 검사를 통과했다. 비공개 적용 기록: `artifacts/damage-effect-chart-20260920/installation.receipt.json`.

분석 페이지의 **효과별로 보기** 체크박스로 전환한다. 기본 해제 상태는 스킬 슬롯별 요약이고, 체크하면 로그에 관측된 개별 공격 효과를 분리한다. 아래 카드도 상위 분류에 묶지 않고 효과별 독립 카드로 표시하며, 제목 옆에 각 피해량과 비율을 둔다. 카드와 막대의 색상을 일치시킨다. 정적 자료의 공격 형태를 대상 지정·전체 대상·순차 공격·지속 피해 등으로 표시한다. 하나의 출처만 관측된 스킬을 임의로 더 나누거나 버프의 가상 기여 피해를 계산하지 않는다. 두 보기 모두 투사체 피해 제외 값과 합계가 같다.

## 2026-09-20 사용자 피드백 반영 — v2 이력

리버렐리오의 헬름·일레그 미분류와 도로시: 세렌디피티의 평타 100% 표시를 대조했다. v1은 같은 tick 안에서만 계산/적용을 연결하여 지연 스킬 피해를 놓쳤고, 기본 캐릭터 스킬만 따라가서 애장품 교체 스킬의 출처도 누락했다.

- **지연 피해:** 전투 전체에서 미소비 계산 후보를 유지한다. 공격자·대상·부위·피해가 일치하는 선행 후보가 유일하거나 모든 후보의 구성 귀속(출처·무기 상태·충돌/폭발 계수)이 같을 때만 분류한다. 동등한 계산은 개수를 보존하고 적용 한 번마다 하나씩 소비한다. 출처가 다른 후보는 미분류로 유지한다. 이 처리는 구성 합계의 귀속이며 계산 이벤트와 적용 타격의 시각을 유일하게 연결했다고 주장하지 않는다.
- **애장품:** `FavoriteItem.NameCode`로 캐릭터를 연결하고 명시된 `SkillChangeSlot`과 `SkillTable`의 교체 root를 따라간다. 실제 로그에서 해당 skill/function 출처가 나타날 때만 슬롯을 붙인다. 정적 대응표에 존재한다는 이유만으로 장착했다고 가정하지 않는다.
- **자동 무기:** `AutoFireWeapon`의 shot 대응과 관측된 스킬 사용을 연결한다. ChangeWeapon 없는 자동 무기를 미분류 또는 평타로 넣지 않는다. UI에 자동 무기 항목을 추가했다.
- **수로시:** 표본의 적용 타격은 모두 기본 shot이고, 정적 스킬은 공격력·펠릿 수·관통·발사 속도 등 사격 강화 경로다. 이 기록의 평타 100%는 타격 출처 기준으로 맞다. 스킬 기여가 0이라는 뜻이 아니며, 버프별 가상 기여 피해를 분배하지 않는다. 평타 항목의 툴팁에 강화 포함 의미를 표시한다.

## 화면 사용

- 상단 구분선 위 **피해 구성 / 타임라인** 버튼으로 화면을 전환한다. 새 전투를 열면 피해 구성이 기본이며, 화면 전환 시 선택 캐릭터와 효과별 보기 상태를 유지한다. 타임라인은 현재 준비 중 화면만 있으며 시간별 분석 데이터는 아직 연결하지 않았다.
- 기존 덱 딜표에서 캐릭터를 클릭하거나 Enter/Space를 누르면 해당 캐릭터 분석으로 이동한다.
- 우하단 **상세 분석 보기**는 덱 전체 분석으로 이동한다.
- 상단 `전체`와 5명 초상화로 분석 대상을 바꾼다. 초상화는 기존 정사각형 SI 자산 경로를 재사용한다.
- **딜표로 돌아가기**는 기존 모달, 목록 필터, 목록 및 페이지 스크롤을 복원한다. 계정·보스가 바뀌면 이전 분석 응답을 버린다.
- 분석 페이지의 `Damage`는 선택한 캐릭터의 **투사체 피해 제외 값**이다. 덱 결과창 총 대미지와 구별한다.

| 분류 | 근거 | 세부 표시 |
| --- | --- | --- |
| 평타 | 타격의 shot 출처가 해당 캐릭터 기본 shot과 일치 | 기본 무기 |
| 교체 무기 | 다른 shot 출처 + 관측된 ChangeWeapon 또는 생성 당시 무기 상태 | 스킬 1/2/버스트 또는 출처 미확인 |
| 자동 무기 | AutoFireWeapon의 정적 shot 대응 + 관측된 해당 스킬 사용 | 스킬 출처 |
| 스킬 직접 피해 | 타격의 skill 출처 | 연결 가능한 스킬 슬롯 |
| 스킬 효과 피해 | 타격의 function 출처 | 스킬 슬롯 및 구별된 효과 항목 |
| 미분류 | 계산/적용 연결 불확실, 출처 미지원, 딜표 잔여 | 임의 배분하지 않은 피해 |

각 분류는 피해, 전체 대비 비중, 적용 타격 수를 표시한다. `타격`은 적용 이벤트 수이며 발사 수나 샷건 펠릿 수로 해석하면 안 된다. 미분류는 타격 수를 추정하지 않는다. 효과 번호는 이 분석 내 표시 순번이며 공식 스킬 이름이나 도메인 식별자가 아니다.

## 집계 원칙

1. DB에서 계정과 battle UID로 기록을 먼저 조회한다. 기존 TAB 값, 투사체 제외 분석 버전·로그 hash·편성 ordinal을 권위로 사용한다.
2. 원문과 manifest의 계정·전투·build·hash·편성·TAB 값이 모두 일치해야 한다.
3. `CommonHurtEvent`의 공격자 소유 관계를 따라 캐릭터에 귀속한다. 적 투사체는 제외하고 monster 대상 적용 피해를 사용한다.
4. 선행 `DamageFormula`의 공격자, 대상, 부위, 피해가 일치해야 한다. v2는 tick 간 지연을 보존하고, 후보가 여러 개라면 위의 구성 귀속 동등성 검사로 제한한다. 서로 다른 출처를 순서나 가까운 시간만으로 임의 연결하지 않는다.
5. 기본 shot 및 스킬 연결은 해당 build의 봉인된 정적 snapshot에서 읽는다. `UseCharacterSkill` 뒤 500ms 이내의 유일한 후보가 정적 교체 대상 shot과 일치할 때 교체 스킬 출처를 연결한다. 후보가 모호하면 교체 자체와 스킬 출처를 별도로 취급한다.
6. 생성 당시 shot/출처를 발사체에 보존하여 기본 무기 복귀 뒤의 지연 충돌·폭발에도 적용한다. 기본 shot과 다르다는 이유만으로 교체 무기라고 단정하지 않는다.
7. `StickyProjectileDirect`는 전용 충돌 계수와 폭발 계수 중 한쪽만 비중립인 경우에 충돌/폭발을 구분한다. 양쪽 중립 또는 비중립이면 세부 구분을 보류한다. 계수를 버프 기여 피해량으로 환산하지 않는다.
8. 모든 캐릭터에 대해 `분류된 피해 합계 + 미분류 = 기존 투사체 피해 제외 값`을 검사한다. monster 적용 합계가 기존 보정값보다 크면 전체를 `total_mismatch`로 보존하고 임의 비율 축소하지 않는다.

이 경로는 기존 조사에서 가능한 모든 연결을 구현한 완전 분석기가 아니다. 검증된 출처만 표시하는 첫 구현이며, 미분류가 0이라는 사실과 모든 스킬 출처가 확인됐다는 사실도 구별한다.

- 분석: `BattleAnalysis/damage-composition-v3/<accountUid>/<battleUid>/<logHash>-<catalogHash>.json`.
- 버전: `damage-composition/v3`. 알고리즘 의미가 바뀌면 버전을 올려 기존 캐시와 분리한다. v1·v2 파일은 과거 결과로 보존한다.
- 최초 열람 시 분석하고 이후에는 동일 원문·카탈로그 hash의 결과를 재사용한다. 동시 분석은 1개이며 대기 제한은 30초다. 이번 구현에 별도 백그라운드 작업 큐는 없다.
- 원문 최대 8MiB, 해제 최대 32MiB 및 이벤트 수 제한은 공통 decoder가 적용한다. 분석 파일은 임시 파일 작성 후 원자적으로 이동한다. 실패 상태를 영구 캐시하지 않는다.
- DB schema 변경 없이 기존 battle UID/ordinal에 연결된 파생 파일을 저장한다. 원문·카탈로그·캐시는 비공개 로컬 자료이며 커밋하지 않는다.
- API: `GET /admin-api/v1/accounts/{accountUid}/raid-records/{battleUid}/composition`. 기존 관리도구 인증을 적용하며 다른 계정의 전투는 404다. 원본 게임 ID와 로컬 경로는 응답에 포함하지 않는다. 피해 정수는 문자열로 반환한다.

## v1 최초 검증과 적용 이력

- 관리 API 단위 검사 589개 통과.
- 기존 실전 4개 기록의 20명에 대해 분류 + 미분류 합계, 캐시 재조회, 계정 범위 제한을 실제 DB 읽기 전용 API로 검사했다.
- 스노우 화이트의 교체 무기 16,293,373,122, 라피의 교체 무기 충돌 1,593,312,162 / 폭발 1,615,499,102가 기존 조사 값과 일치한다. 스노우 화이트 잔여 57,449,411은 미분류로 표시한다.
- 브라우저에서 캐릭터별/전체 이동, 복귀, 큰 정수, 늦은 응답, 결손 상태, 390px 화면을 검사했다. 실제 API 응답 snapshot과 정사각형 초상화로 스노우 화이트 화면을 별도 확인했다.
- 설치본은 UI·관리 API·Persistence 및 로컬 분석 파일을 백업 후 hash 대조하여 교체했다. 기존 DB와 게임 runtime은 변경하지 않았다. 사용자 실제 화면 확인은 별도다.
- 필수 광역 검사도 실행했다. Phase 0·Actions 검사는 통과했으나 repository 검사는 기존 origin remote 정책 충돌, Phase wrapper들은 제한된 NuGet 취약성 조회의 NU1900으로 완료되지 않았다. 전체 repository 검사가 통과했다고 주장하지 않는다.
