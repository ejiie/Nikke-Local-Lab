# 레이드 기록 UI 초안

> 2026-09-27 보관: 작성 당시의 기록이며 현재 작업 지시가 아닙니다. 현행 문서는 [문서 색인](../../README.md)에서 찾습니다.

현재 연결 상태는 [실제 기록 UI](RAID_RECORDS_LIVE.md)를 참고한다. 아래 미연결·설치 전 설명은 초안 검토 당시의 이력이다.

2026-09-20. 운영자는 BattleLog 기반 분석을 관리도구로 연결하기에 앞서, 솔로 레이드 보스 이미지 오른쪽에 모의전·실전 기록 버튼과 속성별 목록을 먼저 배치하도록 요청했다. 구체적인 저장·조회·분석 계획은 이 UI 검토 다음에 정한다.

후속 피드백: 목록의 대미지 아래 ‘투사체 피해 제외값 있음 / 상세 분석 대기’ 문구를 제거했다. 분석값 결손 표시는 상세창에 유지한다. 다음 작업의 제안은 [통계 구현 계획](RAID_ANALYTICS_IMPLEMENTATION_PLAN.md)에 정리했다.

## 이번 작업

- 기존 1:1 보스 카드 오른쪽에 전투 기록 패널.
- 모의전 기록 보기 / 실전 기록 보기 전환.
- 전체·작열·수냉·풍압·전격·철갑·미확인 필터. 실행 설정과 독립적이며 **기록 당시 보스 약점**을 기준으로 한다.
- 최신순 덱 기록 목록: 일시·약점·덱 편성·결과창 총 대미지.
- 기록 클릭 시 상세 팝업: 결과창 총 대미지, 투사체 피해 제외 딜표 합계, 5명 기본 딜표.
- 분석값 결손은 미분석, 원본 값 결손은 미확인. 0을 대신 넣지 않는다.
- 좁은 화면에서는 보스 카드 아래로 패널을 배치.

초안의 조회 범위는 현재 선택 계정과 선택 시즌이다. 서로 다른 시즌의 동일 보스를 통합하는 방식, 전체 계정 비교, 완료 run과 덱 기록의 상위 묶음은 후속 계획에서 확정할 사항이다. 현재 ‘기록 n건’은 덱 기록 개수이며 완료 run 수를 의미하지 않는다.

## 연결 상태

`raid-records.js`는 화면과 필터, 상세창을 담당한다. 선택 계정/보스는 기존 editor.js에서 전달한다. 실제 DB 조회 API 및 BattleLog 분석 작업은 **아직 연결하지 않았다**. 설치본 재배포도 이번 범위에 포함하지 않았다.

제품 코드에는 예시 데이터가 없다. 연결 전에는 ‘기록 조회를 준비하고 있습니다’ 상태를 보여주며, 기록 0건과 구분한다. 선택 해제 또는 계정/시즌 변경 이후 늦게 도착하는 응답은 폐기한다. 필터가 계정이나 시즌을 넘겨 다른 기록을 노출하지 않도록 한 번 더 제한한다.

브라우저 미리보기의 예시 데이터는 tests/editor/raid-records.browser.cjs에만 있다. 테스트는 실제 HTML/CSS/JS를 사용한다. 사진을 넣는 경우 이미 존재하는 로컬 파일만 읽으며 원본 이미지는 소스에 포함하지 않는다. 화면 상단에 ‘예시 데이터 · 실제 전투 기록 아님’을 표시한다.

`loadRecords`에 전달할 화면용 행 형태는 임시 adapter 경계이며 최종 API/DB 계약이 아니다. 큰 피해량은 문자열로 받고 BigInt로 표시해 JavaScript 안전 정수 범위를 넘는 경우도 반올림하지 않는다. 원본 게임 ID는 요구하지 않는다.

## 후속 계획에서 결정할 항목

1. 기존 덱 기록·개인별 딜표·BattleLog의 연결 키와 분석 상태를 읽는 조회 계약.
2. 캐릭터별 적 투사체 피해 차감값, 효과별 분해, 행동 시간표의 저장/조회 범위.
3. 실전의 run → 덱 → 캐릭터 탐색과 모의전 이력의 표시 단위.
4. 로그 없음·분석 실패·미확정 효과를 구분하고 기존 원본 딜표를 유지하는 방법.
5. 유니온 레이드의 시즌 내 다섯 보스로 같은 화면을 확장하는 방식.

위 항목은 이번에 구현한 것으로 보지 않는다. 원본 결과창 총 대미지와 투사체 피해 제외 딜표 합계는 파츠 파괴 등으로 다를 수 있으므로 UI에서도 다른 지표로 유지한다.

## 검사 및 산출물

- 기존 보스 시즌 단위 검사 10개 통과.
- 새 브라우저 검사: 계정/시즌/모드/속성 필터, 최신순 목록, 큰 정수 표시, 미분석, 상세창, Escape, 반응형, 늦은 응답 폐기, 제품 화면 초기화 및 실행 약점 불변 확인 통과.
- source-free 테스트 결과와 스크린샷: `artifacts/raid-records-ui-20260919/browser-final/` (작업 시작일 기준 폴더명).
- 저장소 필수 검사 실행 로그: 같은 상위 폴더의 pre-*/post-*.log. repository 검사는 기존 origin remote 제한, Phase 2A1·2A2·2B·3A·3B-0·3B-1·3B-2는 NuGet 취약성 정보 연결 오류 NU1900으로 막혔다. Phase 0 및 Actions 계약은 통과했다. 전체 게이트나 live PostgreSQL integration 통과를 주장하지 않는다.

이번 작업은 **UI 초안 검토 단계**다. 실제 전투 데이터의 조회·새 분석 DB 저장·설치본 동작 확인은 별도로 수행해야 한다.
