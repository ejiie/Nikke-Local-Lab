# 레이드 기록·BattleLog 통계 구현 계획

> 2026-09-27 보관: 작성 당시의 기록이며 현재 작업 지시가 아닙니다. 현행 문서는 [문서 색인](../../README.md)에서 찾습니다.

후속 상태: 같은 날 운영자가 솔로 모의전 수집 재개, 실제 기록 연결, 개인별 투사체 제외 피해 기본값과 정사각형 초상화를 요청했다. 해당 구현·설치는 [실제 기록 연결](RAID_RECORDS_LIVE.md)을 참고한다. 아래는 그 요청 전의 제안 계획으로, 모의전 보류 및 전 단계 미구현 표시는 현재 상태를 뜻하지 않는다.

2026-09-20. 상태: **제안 계획**. 운영자가 UI 초안을 검토한 뒤 구체적인 연결 계획을 요청했다. 이번 변경은 목록의 대미지 아래 보조 문구 제거와 이 계획 작성까지이며, 아래 저장소·API·분석기는 아직 구현한 것으로 보지 않는다.

## 1. 요구와 현재 상태

사용자 요구는 보스 오른쪽에서 모의전/실전 및 속성별 기록을 보고, 덱 → 캐릭터 → 효과·행동으로 상세 분석하는 것이다. 분석 원천은 BattleLog이고, 기본 TAB 딜표에서 **적 투사체에 가한 피해**를 캐릭터별로 차감한다. 조준·공간 좌표·전체 모션 재현은 범위 밖이다.

현재 코드에서 확인한 기반:

| 구간 | 현재 상태 | 필요한 작업 |
|---|---|---|
| 덱 결과·기본 딜표 | V0027의 관측 부모와 캐릭터/몬스터 자식 테이블에 저장 | 관리도구 조회 계약·API 연결 |
| 전투 문맥 | payload에 run UID, 프로필 revision hash, build, 약점, 시간, 캐릭터 레벨 등 보존 | 조회용 인덱스와 과거 snapshot 해소 |
| BattleLog 원문 | 공용 ProgramData의 비공개 진단 파일 및 battle UID/hash receipt | 지속 저장·회복 가능한 작업 큐·보존 정책 |
| 자동 수집 제한 | 명시적 세션 필요, 최대 10건, 건당 8MiB, 만료 검사 | 운영용 수집 경로로 전환; 제한에 걸렸을 때 원인 표시 |
| 분석 | 로컬 조사 스크립트와 실제 기록 대조 존재 | 버전이 있는 제품용 decoder·분석기·저장소 |
| UI | 모드·속성 필터와 덱 상세 초안, 임시 loadRecords 경계 | 실제 API·분석 화면 연결 |

통계 수집 경로는 Solo Challenge 실전, Union Hard 실전, Union Hard 모의전이다. Solo 모의전은 현재 저장 계약의 지원 모드가 아니며, 이전 운영자 지시로 연결을 보류했다. **버튼이 존재한다는 이유로 지원 완료나 기록 0건으로 표시하지 않는다.** 재개 결정 시 별도 수집 작업으로 포함한다. 이 계획 작성만으로 연결하지 않는다.

현재 솔로 숫자 통계는 로컬 receipt를 먼저 영속화하고 PostgreSQL로 재시도 투영한다. 유니온은 기존 진행 자료와 숫자 관측을 같은 DB transaction으로 저장한다. 이 정상 경로를 유지하며 분석 실패 때문에 전투 결과가 사라지거나 결과 응답이 실패하지 않도록 한다.

## 2. 화면 구성 제안

### 보스 오른쪽 목록

- 현재 선택 계정 · 선택 시즌 · 선택 보스가 기본 범위. 유니온은 시즌 안의 5보스를 각각 구분한다.
- 모의전/실전 버튼 → 보스 약점 속성 필터 → 최신순 덱 목록. 실행용 속성 설정과 분리한다.
- 목록에는 일시, 편성, 결과창 총 대미지를 표시한다. 대미지 아래 분석 안내는 넣지 않는다.
- 같은 보스의 다른 시즌 기록을 보는 기능은 후속 필터로 확장한다. 이름 문자열로 보스를 합치지 않고 로컬 boss UID와 해당 시즌의 전투 구성 snapshot을 사용한다. 통합 조회해도 시즌·난이도·보스 스펙을 보존한다.
- 실전은 상위 run을 펼치면 덱 기록이 보이게 한다. 5덱 완주와 0~4덱 종료를 구분하고, 미완주 run의 실제 덱 결과도 남긴다. 솔로의 일일 참여 기회 소모와 run 완주 판정은 기존 규칙 그대로다. 유니온에 솔로의 5덱 규칙을 적용하지 않는다.
- 모의전은 독립 전투 목록이다. 목록 건수는 덱 전투 수, run 수는 별도 표기한다.

### 덱 상세

기록 클릭 시 다음 순서로 보여준다. 초안의 간단한 팝업을 넓은 상세 패널로 확장하되 목록의 필터·스크롤 위치는 유지한다.

1. 전투 당시 보스·약점·일시·공유 레벨·전투 시간·편성.
2. 결과창 총 대미지와 투사체 피해 제외 딜표 합계.
3. 5명 딜표: 대표 이미지·이름, 기본 TAB 값, 적 투사체 피해, 차감 후 피해, 차감 후 딜표 내 비중, DPS.
4. 캐릭터 선택 시 피해 구성 / 타격 판정 / 버스트 구간 / 행동 시간표.

기본 정렬은 편성 순서, 피해순 정렬은 선택 기능으로 둔다. DPS는 실제 기록된 전투 시간으로 나눈다. 시간 결손이면 계산하지 않는다. 캐릭터 사망 후 시간도 포함하는 전투 전체 DPS와 구간별 DPS를 혼동하지 않는다. 공유 레벨을 한 번 표시하되 실제 기록이 다르면 각각 보존하고 예외를 드러낸다. 전투력은 기본 화면에서 제외한다.

분석 상태·결손 안내는 상세창에만 배치한다. 로그가 없어도 기존 딜표는 열리고, 분석 준비 중이라고 전체 화면을 막지 않는다. 지원하지 않는 모드, 조회 실패, 조회 성공 후 0건은 서로 다른 상태다.

## 3. 지표의 의미와 분해 규칙

### 피해량의 기준

확정 공식은 [원자료 수집 문서](RAID_DAMAGE_CAPTURE.md)를 그대로 사용하며 재검증을 위한 추가 플레이를 요구하지 않는다.

```text
개인 기본 딜표 = Characters[i].Attack.TotalDamage
개인 투사체 제외 피해 = 개인 기본 딜표 − 해당 캐릭터가 적 투사체에 가한 피해
결과창 총 대미지 = 기본 딜표 합계 + 파츠 파괴 추가 피해 − 적 투사체 피해 합계
```

- 아군이 발사한 투사체의 피해를 빼는 것이 아니다. 피해를 받은 대상이 적 투사체인지 확인한다.
- 파츠 파괴 추가 피해를 캐릭터에게 임의 배분하지 않는다. 차감 후 딜표 합계와 결과창 총 대미지를 서로 다른 지표로 유지한다.
- 결과창 값은 request_damage, 서버 승인 값은 accepted_damage로 각각 보존한다. 둘을 합치거나 분석 결과로 덮어쓰지 않는다.
- Skill/StatFunctionAttack 총량은 기본 TAB 값과 중복 가능하므로 더하지 않는다.
- 실제 적용 타격을 기준으로 집계한다. DamageFormula 전체를 피해 발생 횟수로 세지 않는다. 전체 CommonHurtEvent 합계도 TAB 값과 무조건 같지 않다.
- 귀속 못 한 적 투사체 피해는 미귀속으로 따로 남긴다. 다른 캐릭터에 비례 배분하거나 결손을 0으로 채우지 않는다. 필요한 범위가 완전하지 않으면 차감 후 합계를 확정값으로 노출하지 않는다.

### 캐릭터 상세 항목

| 화면 | 지표 | 주의점 |
|---|---|---|
| 피해 구성 | 기본 무기, 교체 무기, 스킬/효과별 피해·횟수·비중 | 한 타격은 하나의 기본 분류에만 포함; 미귀속 항목 유지 |
| 교체 무기 상세 | 발동 스킬, 발동/발사/타격 시각, 충돌·폭발, 대상·부위 | 패시브 발동도 포함; 생성과 타격의 시점 구분 |
| 타격 판정 | 크리·코어·사거리 판정별 타격 수·피해량·피해 비중 | 세 판정은 중첩 가능하므로 합쳐서 100%로 만들지 않음 |
| 사거리 | 타격에 기록된 판정과 적용 계수 | 위치 재구성이나 무기 기본 거리만으로 덮어쓰지 않음 |
| 다단히트·샷건 | 발사 묶음별 적용 타격 수, 부위, 코어/비코어 혼재 | 타격 수와 발사 수는 다름; 식별 불가 펠릿을 빗나감으로 단정하지 않음 |
| 버스트 | 충전, 준비/버스트 체인, 본인 참여 풀버스트, 미참여 풀버스트의 피해·시간·DPS | 단계별 시간을 실제 로그로 산출 |
| 시간표 | 사격, 교체, 스킬, 버프 추가/중첩/제거, 재장전, 회복·피격·사망 | 전투 시작 기준 시각과 동일 tick 내 이벤트 순서 보존 |

버스트 참여는 III만이 아니라 해당 체인의 I·II·III 실제 사용자 전체로 판단한다. 재진입 체인과 전투 종료로 잘린 구간을 처리하며, 체인이 불완전하면 미확인으로 남긴다. 피해 발생 시점의 풀버스트 분류와 교체 무기를 만든 스킬/버스트 출처는 별도 축이다. 스노우 화이트처럼 다음 풀버스트에 발사되거나 라피처럼 충돌과 폭발이 다른 구간에 발생하는 기록을 그대로 보존한다.

효과별 분해에는 적중 당시 활성 버프와 계수의 출처도 연결한다. **관측 피해를 효과 종류로 나누는 것**과 **특정 버프가 없었을 때 피해를 재계산하는 것**은 다르다. 후자의 가상 기여도는 이번 범위가 아니다. 외부 캐릭터가 준 버프를 피해를 낸 캐릭터의 자체 효과로 표시하지 않는다.

타격 판정률에는 판정 가능한 타격 수를 분모로 명시한다. 판정 결손 수를 별도 유지한다. 발사 이벤트·타격 묶음의 연결이 불명확하면 ‘명중률’이나 ‘펠릿 명중률’을 만들지 않고 관측 적중 수만 제공한다.

## 4. 저장·분석 구조 제안

```text
로컬 결과 처리
  ├─ 기존 덱 결과 → 기존 숫자 통계 부모/캐릭터/몬스터
  └─ BattleLog 비공개 원문 + manifest
           ↓ 내구성 있는 분석 작업
      decode → 참조 해소 → 적용 타격/효과/시간 구간 → 검산
           ↓ 버전별 분석 결과
      관리도구 읽기 API → 목록 / 덱 / 캐릭터 상세
```

키는 기존 battle_uid를 중심으로 연결한다. 원본 게임 ID를 PK/FK나 공개 응답에 추가하지 않는다. 신규 테이블명은 구현 시 최종 계약으로 정하되 역할은 다음처럼 나눈다.

| 저장 단위 | 내용·연결 |
|---|---|
| 전투 조회 문맥 | battle_uid, account/run/boss 로컬 UID, 모드·시즌·보스 단계·약점·revision/build·발생 시각 |
| 로그 manifest | battle_uid, 원문 hash·크기·로컬 저장 참조·수집 상태·형식 지문 |
| 분석 실행 | analysis_uid, battle_uid, 원문 hash, decoder/분석 규칙 버전, 정적 데이터 snapshot hash, 상태·진단 코드 |
| 개인 요약 | analysis_uid + 기존 캐릭터 ordinal, 기본/투사체/차감 후 피해, 귀속 완전성 |
| 효과·구간 집계 | analysis_uid + 캐릭터/효과/구간 키, 피해·횟수·시간·판정별 집계 |
| 타격·행동 자료 | 분석 실행에 연결된 비공개 정규화 파일과 시간/캐릭터 인덱스; 필요한 구간만 조회 |

행동 전체를 매번 JSON 응답으로 내려보내지 않는다. DB에는 조회에 필요한 요약·인덱스를 두고 대용량 정규화 이벤트는 비공개 파일로 보존하는 방식을 우선 검토한다. 원문과 정규화 파일의 위치를 브라우저에 직접 노출하지 않는다. 기록 화면을 열 때마다 원문을 다시 해석하지 않는다.

전투 문맥·편성·레벨·착용/스킬 등은 당시 revision으로 해소한다. 현재 편성이나 최신 정적 테이블을 과거 전투에 대입하지 않는다. 과거 자료에서 boss UID 등을 정확히 복원할 수 없으면 unresolved로 남기고 이름으로 추측 연결하지 않는다.

### 운영 조건

- 진단의 10건·만료 세션을 통계의 영구 저장 방식으로 사용하지 않는다. 운영용 수집은 최대 파일 크기, 디스크 사용량과 부족 상태를 관리한다. 초기에는 기존 원문을 자동 삭제하지 않는다. 보존 정책과 백업 복구를 정한 뒤 정리 기능을 도입한다.
- 원문을 원자적으로 저장하고 hash가 포함된 manifest를 남긴다. 파일·DB를 단일 transaction으로 간주하지 않는다. 재시작 후 미등록 manifest를 재발견하고, DB 기록보다 먼저 생긴 파일도 정합성을 확인한 뒤 연결한다.
- 같은 battle UID·같은 hash의 중복은 무효과다. 다른 원문이면 충돌로 보존·진단하며 덮어쓰지 않는다. 같은 분석 버전의 재시도도 중복 집계를 만들지 않는다.
- 분석 상태는 missing/queued/running/partial/ready/failed/unsupported로 나눈다. 재시작으로 멈춘 작업을 회수하고, 실패 원인·재시도 횟수를 남긴다. 필드별 미확정 사유와 전투 전체 상태는 구분한다.
- 분석 규칙이 바뀌면 새로운 analysis_uid를 만든다. 기존 원문·기본 딜표·이전 분석을 유지하고, 검사를 통과한 분석 실행만 화면의 기본 결과로 선택한다.
- build 문자열뿐 아니라 로그 schema 지문·필드 형식과 참조 구조를 검사한다. 모르는 형식을 기존 형식으로 억지 해석하지 않는다. 저장되는 계정·전투 기록은 client 버전 교체와 무관하게 유지한다.
- 압축 해제 크기·레코드 수·참조 수·작업 시간을 제한한다. 손상된 입력이나 분석 실패가 기존 게임 결과 저장/조회에 전파되지 않도록 분리한다.
- 원문·실계정 통계·분석 파일은 로컬 비공개 자료이며 커밋하지 않는다. 검사에는 직접 만든 합성 fixture를 사용하고, 실제 기록 대조 결과는 비공개 artifact로 남긴다.

## 5. 구현 순서와 완료 조건

### 1단계 — 기존 기록을 화면에 연결

기존 DB를 읽는 목록·덱 상세 API와 UI adapter를 만든다. 현재 계정, 레이드 종류, 보스, 시즌, 모드, 약점으로 범위를 제한한다. 최신순은 시각과 battle UID의 안정적인 cursor로 페이지를 나누고, 상세 조회도 계정 범위를 다시 검사한다. 큰 정수는 문자열로 반환한다.

완료 조건: 실제 저장된 편성 5명과 TAB/결과창 값이 화면에서 원자료와 일치한다. 계정·보스·모드·속성을 바꾸어도 다른 범위의 기록이나 늦은 응답이 섞이지 않는다. 로그 없는 옛 기록도 열리며, 미지원 모드를 빈 목록으로 위장하지 않는다. 솔로 run 완주/미완주와 덱 건수를 구분한다.

### 2단계 — 로그 지속 보존과 분석 실행 기반

기존 수집 경로를 운영용 보존으로 전환하고 manifest·작업 큐·버전별 분석 저장을 구현한다. 기존 진단 파일은 battle UID와 hash가 일치하는 것만 가져온다. 원문 없는 과거 통계는 복원된 것처럼 처리하지 않는다.

완료 조건: 중복 수신, DB 일시 중단, 파일 저장 중 종료, 분석 중 재시작, 용량 초과, 미지원 schema를 구분해 복구한다. 기존 전투 결과/숫자 통계는 보존된다. 설치 및 재시작 뒤에도 원문과 전투의 연결이 유지된다.

### 3단계 — 개인별 투사체 제외 딜표

조사 decoder를 제품 코드로 옮기고 적 투사체 식별·공격자 귀속·적용 타격 집계를 연결한다. 개인 요약과 해당 로그의 완전성/미귀속값을 저장해 덱 상세에 표시한다.

완료 조건: 이미 보존된 표본으로 숫자 통계와 개인 귀속을 재현한다. null과 0, 파츠 파괴 추가분, 기타 대상 피해를 구분한다. 새로운 공식을 확인하기 위한 추가 플레이가 아니라 구현이 기존 근거를 보존하는지 검사한다.

### 4단계 — 효과·타격·버스트 상세

평타/교체 무기/스킬 효과, 충돌/폭발, 크리/코어/사거리, 발사·타격 묶음, 본인 참여/미참여 풀버스트 집계를 붙인다. 임시 화면 상태가 아니라 버전별 저장 결과를 조회한다.

완료 조건: 기존 스노우 화이트·샷건·라피 기록의 다단히트, 지연 발사, 패시브 교체, 지연 폭발, 같은 발사체의 서로 다른 크리 판정, 외부 버프 출처를 재현한다. 같은 tick의 단순 순서 매칭으로 피해를 잘못 묶지 않는다. 한 피해가 여러 기본 분류에 중복 합산되지 않고 미귀속 잔여도 보인다.

### 5단계 — 행동 시간표와 통합 사용성

시간 범위·캐릭터·행동 종류 필터, 구간별 누적 피해·버프/재장전/생존 시간을 연결한다. 범위 조회와 페이지 처리로 긴 로그도 열 수 있게 한다. 솔로/유니온은 공통 조회·분석 계층을 쓰고 각자의 모드·보스 선택과 run 의미만 다르게 전달한다.

완료 조건: 동일 tick 순서 및 버스트 경계가 보존된다. 전체 이벤트를 한 번에 렌더하지 않으며 목록 복귀 시 필터가 유지된다. 분석 가능한 일부 항목만 있어도 나머지 화면은 사용할 수 있다.

## 6. 이번 계획의 경계와 다음 착수점

2026-09-20 후속: 기록 목록·기본 딜표와 지속 원문 보존 이후, 사용자가 전용 분석 페이지 및 캐릭터별 피해 구성을 승인했다. 현재 첫 구현 범위와 검증·미분류 제한은 [캐릭터별 피해 구성](RAID_DAMAGE_COMPOSITION.md)을 따른다. 아래의 초기 착수 순서는 계획 당시 기록으로 보존하며 현행 미구현 목록으로 해석하지 않는다.

첫 구현 범위는 **1단계: 실제 DB 목록 + 덱 상세 + 기본 5명 딜표**다. 그다음 지속 수집을 붙여 추가 플레이가 임시 진단 세션 제한으로 유실되지 않게 하고, 개인 보정값과 심화 분석을 순차 제공한다.

보스의 시즌 간 통합 조회, 전체 계정 비교, Solo 모의전 수집 재개, 데이터 자동 삭제 정책은 초기 필수 경로와 분리한다. 앞의 화면 기본값과 저장 구조는 구현을 위한 제안이며 이미 승인·구현된 계약으로 간주하지 않는다.

각 단계의 코드/자동 검사, 설치 적용, 사용자의 원본 게임 및 관리도구 확인은 별도 완료 상태로 기록한다. 기존 통계 공식과 이미 관측된 현상을 새로 검증하라고 반복 요구하지 않는다.
