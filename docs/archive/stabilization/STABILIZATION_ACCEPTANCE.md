# 안정화 변경의 운영자 인수

> 2026-09-27 보관: 작성 당시의 기록이며 현재 작업 지시가 아닙니다. 현행 문서는 [문서 색인](../../README.md)에서 찾습니다.

범위: S-08/S-09 후속 안정화와 현재 문서 정리. 실제 WebView2 화면·원본 게임 조작은
운영자가 한다. 자동 검사/HTTP smoke의 성공을 실게임 성공으로 기록하지 않는다.
배포 및 최종 자동 검사 결과는 [현재 인계](../HANDOFF_2026-09-27.md)의 최신 절을 먼저 확인한다.

2026-09-12 운영자가 아래 테스트에 대해 "모두 정상 동작을 확인했다"고 보고했다.
이번 안정화 변경의 운영자 인수는 완료다. 아래 절차는 재검증용으로 보존하며,
사용자 확인을 새로운 자동 actual-play receipt나 다른 시즌·보스의 검증으로 확대하지 않는다.

## 테스트 전

- 관리도구와 게임을 모두 닫은 상태에서 시작한다. 평소의 **NLL 지휘관 관리 도구**를 연다.
  설치 실행 파일은 `C:\NLL\ControlCenter\desktop\NLL Control Center.exe`다.
- 테스트는 Micron의 기존 151 / S26 경로에서만 한다. 공식 launcher/로그인, S29,
  runtime 선택 파일·hosts·인증서·방화벽의 수동 변경은 하지 않는다.
- 변경 시험은 `Save as..`로 만든 **새 로컬 시험용 계정**에서 한다. 기존 계정은 대조용으로 보존한다.
  시험 계정의 이름은 구분 가능하게 정하고, 테스트 후에도 자동 삭제하지 않는다.

## 수행 순서와 합격 기준

| 순서 | 해볼 동작 | 합격 기준 |
|---|---|---|
| 1. 처음 열기 | 관리도구를 열고 자동 로그인·계정 목록을 확인한다. `목록 새로고침`을 3회 누른다. | 빈 화면/무한 준비/중복 계정이 없다. 새로고침 후 이름·지휘관 레벨·계정 선택이 정확하다. 처음 열기와 반복 새로고침의 대략적인 대기 시간을 각각 기록한다. |
| 2. 계정 분리 | 기존 계정을 선택하고 `Save as..`로 시험용 계정을 만든다. 시험용의 표시 이름 하나를 바꾸고 `Save`한다. 원본과 시험용을 번갈아 선택한다. | 새 계정이 하나만 생긴다. 시험용에만 변경이 있고 원본은 그대로다. 저장 완료 뒤 불필요한 ‘저장 상태’ 패널이 계속 남지 않는다. |
| 3. 수정·재조회 | 시험용 계정의 니케 1명의 레벨을 허용 범위 안에서 변경한다. 큐브 1종의 공통 레벨도 변경해 `Save`한다. `현재 값 다시 읽기`/계정 재선택으로 대조한다. | 저장한 값이 다시 나타난다. 같은 큐브를 장착한 니케에는 공통 레벨이 적용되고, 다른 큐브·계정은 바뀌지 않는다. `저장 이력`에서 기존 revision도 남아 있다. |
| 4. 관리도구 재시작 | 게임이 없는 상태에서 관리도구를 정상 종료한 뒤 다시 연다. 2회 반복한다. | 자동 로그인이 되고 같은 시험 계정·저장 값이 유지된다. 새 revision을 저장한 뒤 준비 상태가 과거 값으로 고정되지 않는다. 시작/종료가 계속 멈추지 않는다. |
| 5. 실제 전투 | 시험 계정에서 `솔로 레이드`의 **시즌 26 프로비던스**와 기존에 검증한 약점을 선택한다. 기존 실행 버튼으로 151을 열고 classic Challenge 화면·스쿼드·전투에 진입한다. 최소 1덱의 전투를 정상 종료해 결과 화면을 확인한다. | 선택한 로컬 계정과 빌드가 투영된다. 원본 전투 화면·보스·HUD·피해량·결과가 정상 표시된다. Museum/다른 시즌으로 바뀌지 않는다. 모의전과 실전 결과를 혼동하지 않는다. |
| 6. 게임 종료·재실행 | 게임을 정상 종료하고 관리도구의 실행 정리가 끝날 때까지 기다린다. 같은 계정으로 한 번 더 실행한다. 마지막에는 게임 → 관리도구 순으로 닫는다. | 이전 실행이 계속 진행 중으로 남아 다음 실행을 막지 않는다. 같은 계정/빌드로 다시 시작된다. 관리도구 종료가 완료된다. `completed`는 실행 정리 완료이지 자동으로 5덱 완주를 뜻하지 않는다. |

총 소요 시간은 전투 길이에 따라 달라진다. 1~4는 관리도구, 5~6은 원본 게임 인수다.
이미 확인한 과거 151 호환성 결과와 이번 변경 후 결과는 별도로 기록한다.

## 문제가 생기면

- 저장이 미확정/pending이면 새 Save를 연타하지 않는다. 원래 요청을 이어 저장하는 화면 안내를
  따르고, 원문 없는 legacy pending/충돌/격리 안내는 그대로 알려 준다. DB 행이나 pending 파일을 지우지 않는다.
- `desktop_start_failed`, `desktop_stop_unproven`, `phase_d_child_deadline_unproven`,
  ownership/hash/rollback 오류가 나오면 멈춘 단계와 코드를 기록한다. 프로세스 이름만 보고
  PostgreSQL/서버를 강제 종료하거나 다음 실행을 반복하지 않는다.
- 알려 줄 것: 실패한 순서, 발생 시각, 누른 버튼, 오류 코드, 재현 횟수, 계정/민감 정보를 가린 화면.
  원본 raw, DB, 토큰, bootstrap 코드, 인증서 또는 게임 파일을 첨부하지 않는다.

## 이번 인수에서 새 기능으로 요구하지 않는 것

P-01~P-09의 전체 My Records 원장·스킨/로비/알림 등 추가 영속화, 약점별 기록 분리,
S29·신규 보스·실드 확장·150 보관 이동은 별도 과제다. 기존 최고점과 진행 상태를 임의로
변환하지 않았으며, 이번 테스트가 그 미구현 기능의 완료 판정을 대신하지 않는다.
